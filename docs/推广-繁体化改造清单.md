# 一、结论（先看这三条，其余都是执行细节）

```
★ 1. 先繁后英：繁体是「零内容成本的增量」，英文是「新内容成本的新市场」。别同时开。
★ 2. 只做「一个 zh-Hant」，不做 zh-TW/zh-HK 两套：两地用词差异极小，
     一套通用繁体 + hreflang 同时声明 zh-TW/zh-HK/zh-MO 即可。
★ 3. 有个前置漏点必须先堵：AI 命书与结账页都是硬编码简体（见 §六），
     否则台湾用户付 $29.99 收到简体万字命书 → 退款 / 差评，比没流量更伤。
     → **2026-10-22 已堵**（locale 全链路 + 繁体禁词判据），详见 §六「实现状态」。
```

# 二、为什么是繁体（收益口径，不是感觉）

| 维度 | 简体站现状 | 繁体增量 |
|---|---|---|
| 支付可行性 | 大陆用户**只能看不能买**（仅国际卡） | 港台马新/北美华人 **卡支付无障碍** |

## 4-2. hreflang 矩阵（每条路由都要一致）

以 `/bazi` 与 `/tw/bazi` 为例，两页各自都要输出完整矩阵：

```html
<link rel="alternate" hreflang="zh-CN" href="https://www.mingcharts.com/bazi" />
<link rel="alternate" hreflang="zh-TW" href="https://www.mingcharts.com/tw/bazi" />
<link rel="alternate" hreflang="zh-HK" href="https://www.mingcharts.com/tw/bazi" />
<link rel="alternate" hreflang="zh-MO" href="https://www.mingcharts.com/tw/bazi" />
<link rel="alternate" hreflang="zh-Hant" href="https://www.mingcharts.com/tw/bazi" />
<link rel="alternate" hreflang="x-default" href="https://www.mingcharts.com/bazi" />
```
- `canonical` **各指自己**（不要跨语言 canonical）
- `x-default` 指简体（大陆 + 未识别地区默认）
- 繁体路由里**不要**再出现 `zh-CN` 的 alternate（避免自指循环）

# 五之二、结构化数据的语言信号（2026-10-26 修）

**修的问题**：根 layout 的 JSON-LD 里 `WebSite.inLanguage` 写死 `"zh-CN"`，
而这段脚本**每个页面都输出** —— 包括 208 个繁体页。
等于在繁体内容里告诉 Google「本站是简体」，与 hreflang 互相打架。

**改法（两层）**：

```
① 根 layout：WebSite 实体去掉 inLanguage
   —— 站点实体不该用"某一种页面语言"标注
② 新增 components/WebPageJsonLd.tsx：页面级 WebPage 实体
   /tw 布局挂载，声明 inLanguage="zh-Hant"
   → 语言由「这一页实际用的语言」决定，不再被根节点覆盖
```

**线上实测（/tw/shengxiao/shu/2028）**：

```
<html lang>                  zh-CN      ← 见下方局限
<main lang>                  zh-Hant
JSON-LD WebPage inLanguage   zh-Hant
hreflang                     14 条
全页 zh-CN 声明              无
```

**简体侧**：`<html lang="zh-CN">` 本身就是标准信号，**不再需要** JSON-LD 语言声明，
所以简体页现在没有 `inLanguage`——这是有意的，不是遗漏。

## 剩余局限（记录在案）

```
<html lang> 仍是 zh-CN —— App Router 里只有根布局能渲染 <html>，
要按路由改必须把全部路由搬进两个 route group（两个 root layout），
对 1300 个静态页是一个大挪动，收益/风险不划算。

补偿（按强度排序）：
① 服务端 JSON-LD WebPage inLanguage=zh-Hant   ← 不依赖 JS，最强
② <main lang="zh-Hant">                        ← 不依赖 JS
③ hreflang 六语系互指                          ← 不依赖 JS
④ LocaleSync 客户端改 document.documentElement.lang  ← 仅对执行 JS 的客户端生效

若将来真的要彻底修 <html lang>，正确做法是 route group 双 root layout，
届时需要同步改：sitemap、tw 布局、以及所有以 /tw 前缀为准的相对链接。
```

# 六、★ 阻塞项：AI 命书语言（不修完，别投港台流量）

> **实现状态（2026-10-22）：已落地，进 verify 链**
> · `src/lib/locale.ts` —— 语言单一事实源（解析/回落/指令/收银台映射）
> · 六个 AI 模块统一 `SYSTEM_PROMPT + localeDirective(opts?.locale)`，**默认路径逐字不变**
> · 8 条 route（unlock/ask/liunian/ziwei/geo/hemun/checkout/membership）下传 locale
> · 收银台繁体映射 `zh-Hant-TW`（SDK 无裸 `zh-Hant`）
> · 繁体禁词别名 註定/積極進取/突破性進展 + 繁体否定词 並非/無/沒有（否则繁体命书**整片绕过**合规校验）
> · `scripts/test-locale-accept.mjs` —— 8 段断言，含「默认与 zh-Hans 逐字相同」「zh-Hant 恰为默认+指令」
> · **仍未做**：客户端还没有写 `mc_locale` cookie 的入口（等方案 C 的 `/tw` 语言切换器）；已落库的历史简体报告不迁移

```
现状：AI 命书 prompt 无语言参数（src/lib 内无 locale 通道）→ 恒输出简体
      结账页 src/lib/waffo.ts:168 硬编码 language: 'zh-Hans'
后果：繁体落地页 → 排盘 → 命书全文简体 → 付费用户看到「不是给我写的」→ 退款/差评
```

**改法（最小）**：
1. 命书/年运/合婚/紫微 的 prompt 构造里加 `outputLocale`，`zh-Hant` 时追加一行约束：
   `「全篇使用繁體中文（台灣用語），干支、十神、納音等術語保持原字，不得簡繁混用。」`
2. 结账页按 locale 传 `language`
3. 报告页/PDF 导出按 locale 选字体（繁体需含 `U+9FA0` 等区，别用缺字字体）
4. 已生成的简体报告**不迁移**（历史订单保持原样）

**验收**：繁体路径走一遍完整购买（排盘→试读→支付→报告），报告全文无简体字（可脚本判定：抽样比对 `简→繁` 转换结果一致性）。
