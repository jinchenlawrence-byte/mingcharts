# 钱包支付真机验收清单（A 项）

> 目的：验证「买家在收银台点 Apple Pay / Google Pay → 扣款成功 → 权益到账」这条链路。
> 目前只验到「按钮可见、会话能创建」，真实扣款未验。本清单给执行人照着做，**不需要看代码**。
>
> 成本：最省一档 **$4.99（追问包 ask_pack）**，退款后实际成本≈0。
> 时间：单次约 15 分钟（不含退款到账）。

---

## 一、设备与前提

| 支付方式 | 必须用 | 不行的组合 |
|---|---|---|
| Apple Pay | iPhone / iPad 上的 **Safari**，或 Mac 上的 **Safari**；设备里 Wallet 已绑一张可用的卡 | Chrome / 安卓 / 微信内置浏览器——Apple Pay 不会出现 |
| Google Pay | **Android 手机上的 Chrome**，或桌面 **Chrome**（Google 账号里已存卡、且账号地区支持） | iOS Safari；中国大陆网络的 Chrome（Google 服务不可达） |

其他前提：

- 一个**测试用普通账号**（不要用运营主账号），已完成邮箱登录，并且已经有一张命盘（追问包需要挂在命盘上下单）。
- 能登录 Waffo Dashboard（看 Payments / Webhook logs）。
- 能登录 Supabase（看 `payments` 表）。只读查询即可。

## 三、下单前先记基线（3 分钟）

1. 登录测试账号 → 打开「AI 追问」页，记下**当前剩余次数**（例：0 次）。
2. Supabase → SQL Editor，记下当前流水条数：

```sql
select count(*) from payments where user_id = '<测试账号UUID>';
```

3. Waffo Dashboard → Payments，确认当前没有进行中的同额订单（避免待会儿认错）。

---

## 四、执行：一条真实钱包支付

按顺序做，每步记下结果。

| # | 操作 | 看哪里 | 期望 |
|---|---|---|---|
| 1 | 测试账号登录 → 定价页 → 选追问包 → 点购买 | 收银台在 `pancake.waffo.ai` 打开 | 收银台正常打开，显示「信用卡/借记卡 + Apple Pay + Google Pay」 |
| 2 | 填写邮箱（若预填则跳过）→ 继续 | 收银台支付步骤 | 三个选项都在 |
| 3 | **点 Apple Pay / Google Pay** → 在弹层里用 Wallet 确认 | 设备弹层 | 弹层出现、显示商户名与金额、指纹/面容验证通过 |
| 4 | 等待跳回我们的成功页 | `/checkout/success?ref=MC-…` | 页面显示处理中 → 已解锁/报告入口出现 |
| 5 | 查数据库 | Supabase：`select * from payments where transaction_id='PAY_…'` | **1 行**，`status=paid`，`sku=ask_pack`，`amount=4.99`，`payment_method=applepay|googlepay` |
| 6 | 查 webhook | Waffo → Developers → Webhooks → Deliveries | 该笔为 `success`，HTTP 200 |
| 7 | 查权益 | 「AI 追问」页 | 剩余次数 **+ 该包的次数**（例：0 → 包内次数） |

**第 5 步是 B 项的答案**：如果 `payment_method` 显示 `card` 而不是 `applepay`/`googlepay`，把 Waffo Deliveries 里那条 payload 的 `paymentMethod` 原值截图记录（不影响权益，只影响记账准确性）。

**判定**：第 5、6、7 步都符合 → **A 项通过**。任一步不符 → 记下卡在哪一步，按《应急-付了钱没权益-排查手册》处理，并把现象回报。

## 五、退款与「权益是否回收」

### 5.1 退款走哪里

Waffo Dashboard → **Payments** → 点开该笔（用第 5 步的 `PAY_…`）→ **Refund** → 选**全额 / Full** → 确认。

（不要在我们的站点或 Supabase 里退，退款只能从 Waffo 侧发起。）

### 5.2 退款后要核对什么

| 时间点 | 看哪里 | 期望 |
|---|---|---|
| 退款后 1–2 分钟 | Waffo Payments | 该笔状态变 `Refunded`（或 `Partial Refund`），有退款单号 |
| 退款后 1–2 分钟 | Waffo Webhook Deliveries | 新增一条退款事件投递，`success` |
| 退款后 | Supabase `payments` | 同一行 `status` 变 **`refunded`** |
| 退款后 | 我们的「AI 追问」页（刷新/重登） | 该包次数**被扣回**（例：包内次数 → 0） |

> 一次性商品（含追问包、报告）的退款**会**回收权益，这是设计行为。
> 如果刷新后次数没有扣回，先退出重登再试；仍然没扣回，记下来回报——这是需要修的缺陷。

### 5.3 会员为什么不能拿来做退款测试

`member_monthly` / `member_yearly` 的退款**不会**撤销会员（会员只由 `subscription.canceled` 终止）。
买会员再退款 = 白拿一个账期。**不要用会员做本项验收**；会员的钱包扣款另行单独验，且不退。

## 七、不要做的事

1. 不要在用户未确认前自行发起真实扣款（本清单只作准备，执行需明确授权）。
2. 不要用运营主账号下单，避免污染真实账务与权益。
3. 不要为「试一下」重复下单——重复扣款要逐笔退，很麻烦。
4. 不要用会员做退款测试（见 5.3）。
5. 不要在 Supabase 里手工改这笔测试流水的金额或 `transaction_id`。
