# 〇、先定判断标准（否则又会加出问题）

## 0.1 ★ 两条准入标准

```
标准一：这条权益【随时间持续产生新内容】吗？
         ├─ 是 → 属【订阅】
         └─ 否 → 属【报告】（一次性、可留存、重）

标准二：加了它之后，$29.99 的命书是【更难卖】还是【更好卖】？
         └─ 让它更难卖的，不加
```

## 0.2 由此得出的分界线

```
订阅：轻 · 短 · 频繁 · 个人化     日运一句 / 流月提示 / 交运提醒 / 追问回答
报告：重 · 深 · 一次性 · 可留存   命书万字 / 年运详批 / 合婚九维 / 紫微十二宫
```

**★ 并且明确禁止"无限"** ——
本次 P0 的成因就是「不限次数」：边际成本不可控，且必然侵蚀单次商品。

# 二、建议加入的权益（按性价比排序）

## 🥇 ① 多命盘管理（自己 ＋ 家人）—— **最便宜的强权益**

```
免费：1 个命盘
订阅：3–5 个（自己 + 父母/配偶/子女）
```

| 维度 | 评估 |
|---|---|
| 边际成本 | **≈0**（`/charts` 页已实现，只需加数量上限判定） |
| 感知价值 | **高** —— 「给爸妈也排一个」是真实且高频的需求 |
| 与报告重叠 | **无** —— 报告是内容，命盘是"存档位" |
| 持续性 | ✅ 每加一个家人 = 一次订阅理由 |

**★ 而且它天然驱动订阅**：家人越多，越倾向于订阅 ✓

## 🥇 ② 交运提醒（大运切换节点）—— **命理上真正重要的节点**

```
「你将在 2031 年 3 月交入【戊子】大运 —— 比劫夺财，宜守成。」
（数据来源：LuckDaYunItem.startYear / shiShenGan / tag / relations，均已存在）
```

| 维度 | 评估 |
|---|---|
| 边际成本 | **≈0**（确定性计算，可预生成） |
| 感知价值 | **高** —— **懂命理的人最在意的就是"什么时候换运"** |
| 与报告重叠 | **低** —— 报告给十步大运**逐一详批**；提醒只给**下一个节点 ＋ 一句提示** |
| 持续性 | ✅ 可做"倒计时"（距交运还有 N 年 N 月），**天然复访** |

**★ 这是我认为最被低估的一条** —— 它不新造内容，但命理用户**真的在意**。

## 🥈 ③ 相似古籍命例对照 —— **我们独有的资产**

```
「与你的命局结构相似的古籍命例 12 例（附出处与多流派断语）」
（searchSimilarCases 已返回 source 与 readings[]）
```

| 维度 | 评估 |
|---|---|
| 边际成本 | **≈0**（函数与数据都已存在） |
| 感知价值 | **中–高**，且**独一无二** —— 别人没有带出处的古籍命例库 |
| **战略价值** | **强化我们的定位**：「讲依据、有出处、不是话术」 |
| 与报告重叠 | ⚠️ 需划清（见下） |
| 持续性 | ⚠️ 偏静态 —— 但**随流年变化，相似命例的对照解读可变** |

**⚠️ 与命书划清**：

```
命书：  策展的 N 条，嵌在报告上下文里（"你的情况，古籍有类似记载…"）
订阅：  可检索、可多流派对照的【完整视图】（自己翻、自己比）
```

## 🥈 ④ 流月提示（每月）—— 与年运报告划清粒度

```
「本月【丙午】，官星得力 —— 宜推进；注意与日支相冲的两日。」
（LuckLiuYueItem 已含 ganZhi/jieQi/tag/relations）
```

**⚠️ 必须与 $19.99 年运报告划清**：

```
订阅：  当月【一句话】提示（轻、短、频繁）
年运报告：十二个月【逐一详批】＋ 岁运结构分析（重、深、一次性）
```

## 🥉 ⑤ 历史日运回看

```
「回看过去 30 天的日运」
```

边际成本 ≈0，感知价值中低，**顺手加** ✓ 且它让"日运"从"看一次"变成"有记录" ✓

## 🥉 ⑥ 日签分享卡片（高级样式 / 去水印）

- 基础日签**免费**（获客，见设计稿 §2.3）✓
- 订阅给"高级样式/自定义署名" ✓ 边际成本 ≈0

# 三、V2：追问额度（最强钩子，但需限量）

```
订阅含【追问 15 次/月】—— 对个人命盘的追问问答
```

| 维度 | 评估 |
|---|---|
| 边际成本 | **有**（AI 调用）→ **必须限量**，不设"无限" |
| 感知价值 | **最高** —— FateTell 的核心粘性就是「大司命对话」 |
| 与报告重叠 | **低** —— 追问是"短问短答"，报告是"万字详批" |
| 前提 | **须单独立项设计**（拒答清单、改写法、运行时合规检查 —— 见 `定价方案.md` §8.1） |

**★ 追问上线后，可考虑把年订阅从 $49 提到 $69** ✓（到那时订阅有了最强钩子）

# 四、明确**不建议**加的

| 不加 | 为什么 |
|---|---|
| **任何"无限"** | 正是本次 P0 的成因；边际成本不可控 + 必然侵蚀单次商品 |
| **命书 / 年运 / 合婚 / 紫微 / 地理** | 用户已拍板：**订阅不含报告** |
| **人工解读 / 连麦** | **平台明令禁止**（Waffo「Digital delivery only」：不得是"人的时间"） |
| **连续签到奖励 / 断签提醒** | 红线：不做成瘾式机制 |
| **"运势下滑"类召回** | 红线：不做恐吓式推送 |

# 五、补齐后的订阅价值与定价

## 5.1 价值对照

| | 补权益前 | **补权益后** |
|---|---|---|
| 每日 | 个性化日运 | 个性化日运 ＋ 历史回看 |
| 每月 | 流月更新 | 流月提示 |
| 每运 | — | **交运提醒（含倒计时）** |
| 随时 | — | **多命盘 3–5 个** ＋ **相似古籍命例对照** |
| V2 | — | **追问 15 次/月** |

**→ $49/年（≈$4/月）在这个包里是站得住的** ✓

## 5.2 是否调价（供你选）

| 方案 | 月付 | 年付 | 年付相当于 |
|---|---|---|---|
| **A（维持）** | $9.90 | $49 | **≈5 个月** |
| B（更推年付） | $12.90 | $49 | **≈3.8 个月** |
| C（V2 后提价） | $9.90 | **$69** | ≈7 个月 |

**我方建议：先 A，追问上线后转 C** ✓
**理由**：月付价是"试用门槛"，现在贸然提到 $12.90 会让首月转化变差；
**等追问把价值撑起来，再同时提年付价更稳。**

# 七、一句话

> **"订阅给得太少"这件事，其实不难解 —— 因为我们要加的东西【几乎都已经在代码库里了】：**
>
> **相似古籍命例对照**（`searchSimilarCases` 已带出处与多流派断语）、
> **交运提醒**（`LuckDaYunItem` 已有 startYear/十神/tag）、
> **流月提示**（`LuckLiuYueItem` 已齐）、
> **多命盘**（`/charts` 页已实现）。
>
> **所以补权益主要是"把已有资产开放出来"，边际成本 ≈ 0，感知价值却很高。**
>
> **而两条准入标准是**：
> **① 它随时间持续产生新内容吗？**（否则属报告）
> **② 加了它，$29.99 的命书是更好卖还是更难卖？**（更难卖的不加）
>
> **并明确禁止"无限"** —— 那正是这次 P0 的成因。
>
> **我最看好的三条**：**多命盘**（最便宜且天然驱动订阅）、
> **交运提醒**（命理用户真正在意、却被低估）、
> **相似古籍命例对照**（我们独有，且强化"讲依据"的定位）。
>
> **最强的仍是 V2 的追问** —— 但必须**限量**，且须单独立项设计。
