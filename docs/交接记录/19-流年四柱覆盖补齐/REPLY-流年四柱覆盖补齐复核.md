## 2.1 ★★★★ `cap` 与阈值未同步校准 —— 「1 个结构病」的封顶松了一档

**这是本轮最需要处理的一处，因为它【削弱了事故 18 的纪律】。**

```ts
// 现状（analysis.ts fortuneTierOf）
const cap =
  structuralIssues.length === 0 ? 4 :      // 无结构病 → 可达「大吉」
  structuralIssues.length === 1 ? 2 :      // 1 个     → 最高「小吉」   ← ★ 注释这么说
  0                                        // ≥2 个    → 最高「平」
const s = Math.min(score, cap)

if (s >= 3) return '大吉'    // ← 新阈值
if (s === 2) return '吉'     // ← ★ 所以 cap=2 实际给出「吉」✗
if (s === 1) return '小吉'
```

**★★★ 两个问题叠在一起**：

```
① ★★★★ 【注释与实际不符】✗
   注释写「1 个 → 最高「小吉」」✗
   而新阈值下 min(s,2) 最高 = s=2 = 「吉」✗
   → ★★★★★ 这是 §8.6.7 的老问题：注释文字不能代表实际行为 ✗

② ★★★★ 【事故 18 的纪律被削弱一档】✗
   原设计：1 个结构病 → 最高「小吉」（第 3 高）✓ 保守 ✓
   现状：  1 个结构病 → 最高「吉」  （第 2 高）✗
   → 而 cap 只封【分数值】✗，它对应的【档位】随阈值一起下移漂移了 ✗

```
