
> **没写明"`非命例: true` 的文件必须整体排除"**。这条是我的疏漏。

## 🔴 P0-2：去重偏好「文本更长」，导致劣质记录胜出

### 现象（阎锡山，四柱正确但断语错）
```
用户库展示: 癸未 辛酉 乙酉 丁亥 | 阎锡山 | 子平真诠评注(徐乐吾评注本)
  text = '，辛金透，丁火刚，秋木盛，三者皆备，极等之贵，以其有力也。
          官强财透，身逢禄刃，如丙生子月，癸水透，庚金露，而坐寅午，三者皆均，遂成大贵…'
```

**这条文本有两个问题**：
1. **以「，」开头** —— 明显是截断的残片
2. **后半段是无关段落** —— "如丙生子月，癸水透，庚金露…" 举的是**丙火日主**的例子，
   与阎锡山（乙木日主）无关。这是把书里**下一段泛论"有力"**的文字并进来了

而同一命例在 `cases-zp-llm.jsonl` / `cases-gist-llm.jsonl` 里是**干净的**：
```
断语 = '辛金透，丁火刚，秋木盛，三者皆备，极等之贵，以其有力也'
```

### 根因
`build-mingli-cases.mjs:72`
```js
if (c.person && (!existing.person || c.text.length > existing.text.length)) {
  seen.set(key, c)
}
```
**`c.text.length > existing.text.length` —— 更长 ≠ 更对。**
`cases-ziping-mingli.jsonl` 的坏记录因文本更长，**覆盖了**干净版本。

### 修复
去掉"更长为优"，换成**按来源质量等级排序取最优**：
```js
// 优先级：文件质量等级 A > B > C；同级再看是否有 person
const gradeRank = { A: 3, B: 2, C: 1 }
if (rank(c) > rank(existing)) seen.set(key, c)
```

> 交接书里"阎锡山命盘（癸未 辛酉 乙酉 丁亥）**精确命中**"——**四柱对，断语错**。
> 这个说法只对了一半。

## 🔴 P0-3：聚合文件污染（先读到的劣质记录被锁定）

### 现象

另外建议：`person` 为空时也应允许"更长文本"替换（但优先级低于质量等级）。

# 五、另两个模块的审核意见

## 5.1 合婚模块 ⚠️ 评分口径偏松

```js
let score = 60        // 基础分
...
const totalScore = Math.max(0, Math.min(100, Math.round(score)))
const grade = totalScore >= 85 ? '上等良缘'
            : totalScore >= 75 ? '上等婚配'
            : totalScore >= 65 ? '中上等婚配'
            : totalScore >= 55 ? '中等婚配·宜多经营'
            : ...
```

**问题**：基础分 60 意味着——
- 七维度**全部中性**也得 **60 分**（落在"中等婚配"）
- 要到"下等"须净亏 5 分以上
- 实测样本直接拿到 **86 分「上等良缘」**

**有效区间被压缩在 55–100**，导致**评级普遍偏高**，有"讨好用户"的观感。

**建议**：
- 基础分降到 **40–50**，或
- 改为**分项展示**（七个维度各自的结论）+ 一句总评，弱化"86 分"这种伪精确数字
- 命理合婚本无"打分"传统，**给一个精确到个位的分数反而显得不可信**

## 5.2 地理模块 ⚠️ 城市五行混用两套不相容依据

数据字段：`wx`(主五行) / `wx2`(次五行) / `reason`(取象依据)。抽查：

```
北京      wx=土  reason="古都皇城居中原之北，厚土载物；政金肃敛"
大连      wx=水  reason="黄渤海良港，航运造船属水"
太原      wx=金  reason="煤铁之乡、能源重工，盆地土生金"
长春      wx=木  reason="森林城、汽车城，黑土地上木气生发"
```

**问题：混用了两套互不相容的体系**

| 体系 | 依据 | 北京的判定 |
|---|---|---|
| **方位五行**（命理正统） | 东木/南火/西金/**北水**/中土 | 北京在**北** → 应判 **水** |
| **物产/产业取象**（现代发明） | 皇城=土、煤铁=金、港口=水、森林=木 | 北京 → 判 **土** |

**同一份数据里两个标准并存**：大连按"方位"判水（在北）✓ 也按"港口"判水 ✓，
但北京按方位该是水、按物产判了土 —— **标准不一致**。

**更关键的是：`reason` 里没有一条引古籍。** "厚土载物""政金肃敛"是现代人的推演，
**不是命理典籍里的依据**。而 `wx` 直接参与打分（"城市主气合目标 +28"），
**等于把一个现代发明包装成命理结论卖给用户**。

**建议**：
1. **明确声明体系**：在页面上写清"城市五行取象为本产品设定，非古籍原文依据"
2. **统一标准**：要么全用方位五行（有典籍依据），要么全用物产取象（明确标为自创）
3. **优先方位五行**——它是唯一有命理传统的（东方木/南方火/西方金/北方水/中央土），
   物产取象可作为**次要**参考并标注

> 这一点与我们做命例库时反复强调的纪律是同一个道理：
> **自己推演出来的东西，必须标明是自己推演的，不能冒充古籍。**
