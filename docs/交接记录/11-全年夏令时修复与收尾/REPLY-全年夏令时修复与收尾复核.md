# 四、⚠️ 但我发现一处残留（你自列为缺项 4，我认为应当修）

## 4.1 事实

`ai-check.ts` 作为共享判据是正确的 ✓，**但两个消费者的"接线"不对称**：

```ts
// aiHemun.ts:161  validate 含禁用词
findForbidden(Object.values(s).join(''), true).hits.length > 0

// aiAnalysis.ts:282  validate 只查干支
(r) => unknownGanzhi(Object.values(r).join(''), facts).length ? '检出未溯源干支' : null
```

## 4.2 我实测的后果

```
句子                findForbidden    aiAnalysis 的 validate    是否会漏出去
此事不必强求         命中[必]          只查干支                  ✓ 被 sanitize 替换
此事未必如愿         无（否定式豁免）    只查干支                  ✓ 不构成违规（豁免正确）
竞争压力不可避免      无（否定式豁免）    只查干支                  ✓ 同上
务必谨慎行事         命中[必]          只查干支                  ★ 会漏出去
势必有所取舍         命中[必]          只查干支                  ★ 会漏出去
必定如此            命中[必]          只查干支                  ★ 会漏出去
```

**→ 「务必 / 势必 / 必定」这类绝对化断言，会从 aiAnalysis 直接上线。**

（sanitize 只覆盖「不必」；而「未必」「不可避免」被 `findForbidden` 的否定式豁免正确放行，
**这两个不是问题**。）

## 4.3 为什么我认为该修

**讽刺之处在于**：`ai-check.ts` 的**设立初衷就是"单一事实源、防漂移"**（你上一轮的原话）。
**判据确实统一了 —— 但接线漂移了。**

| | aiHemun | aiAnalysis |
|---|---|---|
| 共享判据 | `ai-check.ts` | `ai-check.ts`（同一个） |
| validate 接线 | `findForbidden` + `unknownGanzhi` | **只有 `unknownGanzhi`** |

**「单一事实源」只保证了"判据一致"，不保证"每个消费者都调用了它"。**

**建议**：把 `findForbidden` 加进 aiAnalysis 的 validate（与 aiHemun 对称）。
**这不是"扩大 AI 行为变更面"，而是消除一处不一致** ——
失败模式是"绝对化措辞上线"，而"禁绝对化"是本项目的红线之一（也是 App Store 合规要点）。

## 4.4 顺带：缺项 4 里"重试只管干支"这个描述可以更新

你写「重试只管干支溯源」——**准确**。但建议在注释里加一句
**"与 aiHemun 不对称，待补齐"**，否则下一个人会以为这是有意的设计。

（**§8.4.4 的老规矩：刻意的设计要显式说明；非刻意的差异更要说明。**）
