## 三、关键设计事实（任务书点名要求回执写明的）

1. **协议**：同命主多轮连续（与官方 Multi-turn 同做法）：system → 排盘 → 合成 ack（「收到排盘信息，我已仔细阅读完毕，请提问。」）→ 问题逐轮、回复逐轮入上下文。固定 temperature=0、max_tokens=1024、`current_year` 以「现在时间是 X 年」附于首条 user message 末尾。
2. **反作弊**：评测脚本从数据结构上就不可能泄漏答案——`buildQuestionMessage` 只接收 question 与 options 两个字段，`answer` 在评分侧才被读取；断言①＋牙口①双向守护。
3. **时区**：16 种 place 字面量映射无 fallback；tzdata 历史偏移自动处理并实测验证（马来西亚 1982 前 +7:30 共 5 人、香港 1962/1967 DST、中国大陆 1990-05-23 DST、美国 1974 全年夏令）。敏感性核验：「美国」美东 vs 美西四柱相同、马来西亚 +7:30 vs +8 平读四柱相同——粗粒度地名的歧义经量化无害。
4. **current_year 必须喂** ✓（题在问「现在」）；contest_id/total_questions/description/categories 均未喂（断言①覆盖）。
5. **缺字段如实缺**：prompt 文末固定【本盘缺字段说明】：神煞（八字神煞表）、胎息、精确起运日期与交运时间——不编造、不用别的数据凑。
6. **可复现**：断言④同一命主排两次完全一致（3 人抽验）；评测断点续跑（doneIds）、每答一题落盘一次。
7. **本任务未改动产品代码**：只新增 eval 侧脚本与数据；package.json 仅 verify 链追加一段。
8. **C 组不可行的证据**：本产品规则引擎输出是结构化事实（关系/结构病/7 档判词/分维度），而 Contest8 的题是具体人生事件（「命主已经离婚，第二婚是哪一年？」「父亲是哪一年仙逝？」）。任取 enhancedFacts（见 paipan-results.json），其中没有任何字段能直接映射到 A/B/C/D 选项文本——把结构化事实映射到选项必须有 AI 或人工规则承担推理，这正是 B 组在测的东西。故 C 组不跑，这不削弱任务价值（B 组即价值主张的测量）。

## 八、缺项（如实承认）

1. **C 组未跑**——不可行，证据见 §三-8（任务书 §4.3 预期内）。
2. **缺字段未补**：神煞、胎息、精确起运日期（solarQiYunDateStr）、交运说明（solarJiaoYun）；干支关系仅覆盖冲/合（天干五合/地支六合）/刑/害，缺暗合/破/三合全局。已在每个 prompt 文末【本盘缺字段说明】告知模型——模型看不到这些信息，构成与官方基线的可比性限制。
3. **维度分类为自建关键词规则**：数据集 categories 为空数组、官方分类脚本未开源；「其他」维度占比最高（69/200），分维度数字仅供方向性参考。
4. **官方排盘结果未开源**：用自己的 paipan 引擎排盘（已与官方 §4.2 范例逐字段交叉验证一致），但口径差异不能排除——数字不是严格同条件对比。
5. **单次测量**：官方为多次运行宏平均，我们 temperature=0 单次；点估计方差更大（2024 年 −10pp 波动即可能源于此）。
6. **ack 为合成固定语句**（官方为模型真实回复）——为换取确定性。

## 九、待拍板

1. **B 组净增益 −1 题（−0.5pp）怎么用**：本次测量下「往 prompt 里塞结构化事实」没有带来准确率提升。可选后续：改事实呈现方式（如只给当前大运+关系，不给九步全表）、换更强模型重测、或接受「AI 准确率与通用模型持平」的产品定位。建议方向性讨论后再投入。
2. **2024 年 B 组 −10pp 是否复测**：单次抽样方差 vs 系统性干扰不可分辨；如需区分可做 3 次重复测量取均值（成本约 3×token）。
3. **结果文件是否入库**：`eval/baziqa/results/*.json`、`paipan-results.json`、`report.md` 为评测产物；断言⑥依赖这两份结果文件存在（verify 在无产物的新环境会红）。若不入库需把⑥改为「产物存在才跑」的软断言；若入库则 verify 可全环境复现。
4. **「其他」维度 69/200**：自建分类器粒度粗，是否值得人工标注一遍以获得更可信的分维度结论。
5. **demo/产品侧无需改动**：本任务零产品代码改动；是否要把「外部基准」结论沉淀进产品文案，属产品决策。
