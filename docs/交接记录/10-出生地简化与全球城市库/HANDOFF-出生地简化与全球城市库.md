# 一、目标 UX（用户原话）

> 1. 让客户选择自己的城市，**确定城市后后台自动校准时区**
> 2. 选项里没有出生城市时，提供「**其它**」，再让客户**手动选择时区**；
>    排盘页下方附说明：选项内找不到出生城市，可手动选择时区
> 3. 城市选项太少 —— **应包含世界所有国家的城市**；面向北美，所以
>    **先选国家 → 再选州/省 → 再选城市**，且**可点选、也可输入搜索**

## 1.1 交互设计

```
出生地
  ┌──────────────┬──────────────┬────────────────────┐
  │ 国家 ▾       │ 州/省 ▾      │ 城市 ▾             │
  │ United States│ California   │ San Francisco      │
  └──────────────┴──────────────┴────────────────────┘
  或直接搜索：  [ 🔍 输入城市名…                      ]
                → 结果列表：San Francisco  United States · California
                             New York       United States · New York

  中国用户选「China」后：北京 / 上海 / 广州 …（中文名）

  选中后显示：San Francisco, California, United States
              （时区 America/Los_Angeles 由后台自动确定）

  ── 找不到出生城市？ ──
  [ 其它（手动选择时区）▾ ]   → 时区下拉 + 「夏令时按出生日期自动判定」
  排盘页下方说明：若选项内无法找到出生城市，可选「其它」手动指定时区。
```

> **命名范围**：中国城市用中文名，外国城市用英文名（见 §3.4）。

## 1.2 三条硬要求

| # | 要求 |
|---|---|
| 1 | **时区由城市自动带出，用户不填** |
| 2 | **「其它」→ 只选时区**（★ 不再要求填经度） |

# 二、★ 技术前提：「其它」路径怎么算真太阳时（**已实测验证**）

## 2.1 问题

真太阳时公式是：

```
真太阳时 = 本地钟表时刻 + (经度 − 当地实际UTC偏移 × 15) × 4 分钟
```

**只选时区、没有经度时，经度取什么？**

## 2.2 ★ 关键：必须取「**标准**中央经线」，不是「当时偏移」的经线

**直观理解**：不知道经度时，只能假设用户就在**该时区的标准经线上**。
此时经度校正为 0，**但夏令时仍必须剥掉**（因为用户填的是钟表时间）。

```
标准中央经线 = min(该时区【1月15日】偏移, 【7月15日】偏移) × 15
```

> **为什么取 min**：夏令时恒为 "+1 小时"，所以标准偏移在数值上总是**较小**的那个。
> 这条规则**同时适配南北半球**（悉尼 1 月是夏令时 +11、7 月是标准 +10 → min 取 +10 ✓）。

## 2.3 已实测验证（**6/6**，请照此对表）

| 场景 | 时区 | 1月偏移 | 7月偏移 | 标准经线 | 校正 | **真太阳时** |
|---|---|---|---|---|---|---|
| 纽约 1990-07-01 14:30 | America/New_York | −5 | −4 | −75 | −60 分 | **13:30** ✓ |
| 纽约 1990-01-15 14:30 | America/New_York | −5 | −4 | −75 | 0 分 | **14:30** ✓ |
| 洛杉矶 1990-07-01 08:30 | America/Los_Angeles | −8 | −7 | −120 | −60 分 | **07:30** ✓ |
| 北京 1990-01-15 14:30 | Asia/Shanghai | +8 | +9 | 120 | 0 分 | **14:30** ✓ |
| **北京 1988-07-01 14:30** | Asia/Shanghai | +8 | +9 | 120 | −60 分 | **13:30** ✓ |
| **悉尼 1990-01-15 14:30** | Australia/Sydney | +11 | +10 | 150 | −60 分 | **13:30** ✓ |

## 2.4 ⚠️ 现行实现会算错（差 60 分钟）

现行 `resolveBirthRef`：

```ts
if (args.manualLng !== undefined && Number.isFinite(args.manualLng)) { ... }
if (args.city) { ... }
return null                      // ← 只给 zone、不给 lng → 返回 null → 偏移 0
```

**结果**：只选时区时**完全不校正**，夏令时没剥掉：

```
纽约 1990-07-01 14:30 → 偏移 0 → 14:30   ★ 应 13:30，差 60 分钟
北京 1988-07-01 14:30 → 偏移 0 → 14:30   ★ 应 13:30，差 60 分钟
```

**而 60 分钟在时辰边界上足以改变时柱。** 这是本任务书必须一并修掉的。

## 2.5 精度说明（要写进 UI）—— **★ 已修正：不是 ±30 分钟**

「只选时区」时我们**假设用户在标准经线上**。但这个假设的误差**随时区不同，差别很大**。

### 实测（1990 年，同一口径）

| 地区 | 城市 | 标准经线 | 实际经度 | **误差** |
|---|---|---|---|---|
| 北美 | 纽约 | −75 | −74.0 | +4 分 |
| 北美 | 丹佛 | −105 | −104.99 | 0 分 |
| 北美 | 洛杉矶 | −120 | −118.24 | +7 分 |
| 北美 | 温哥华 | −120 | −123.12 | −12 分 |
| 澳洲 | 悉尼 | 150 | 151.21 | +5 分 |
| 澳洲 | 墨尔本 | 150 | 144.96 | −20 分 |
| 澳洲 | 阿德莱德 | 142.5 | 138.60 | −16 分 |
| **澳洲** | **达尔文** | **142.5** | **130.84** | **−47 分** |
| 澳洲 | 爱丽斯泉 | 142.5 | 133.87 | −35 分 |

### 结论：误差界要按地区说

```
北美等"时区经线居中"的地区  →  多数在 ±15 分钟内
政区跨度大 / 经线偏置的地区  →  可达 ±50 分钟
```

**为什么澳洲特别差**：**澳洲的时区中央经线是按东海岸定的**（150°E 穿过墨尔本—悉尼一带），
而**南澳/北领地实际在其以西很远处**（130–141°E）——
**ACST 的标称经线 142.5°E 根本不在它的使用区里**。

### UI 文案（据此写）

> 未填经度时按所选时区的中央经线估算。**多数地区误差在 ±30 分钟内，
> 个别时区（如澳大利亚中部）可达 ±50 分钟。**

### 因此的排序建议

```
① 优先：用搜索找到具体城市  → 有精确经纬度 → 零误差
② 其次：从下拉里选最近的较大城市
③ 最后：「其它」只选时区     → 有上述误差
```

**「其它」是最后手段，不是默认路径。** UI 上要引导用户先试搜索。

# 三、数据：全球城市库

## 3.1 数据源：GeoNames（已确认）

| 项 | 内容 |
|---|---|
| 来源 | `download.geonames.org/export/dump/` |
| 许可 | **CC-BY 4.0 —— 必须署名**（页脚加"城市数据 © GeoNames (CC BY 4.0)"） |
| 文件 | `cities15000.zip`（>15000 人或首都，**约 2.5 万城**）<br>`admin1CodesASCII.txt`（州/省英文名）<br>`countryInfo.txt`（国家名与代码） |
| 关键 | ★ **geoname 表第 18 列就是 IANA 时区 id** —— 正好满足"选城市自动带时区" |

**geoname 表列序**（制表符分隔，UTF-8）：

```
1 geonameid | 2 name | 3 asciiname | 4 alternatenames | 5 latitude | 6 longitude
7 feature class | 8 feature code | 9 country code | 10 cc2
11 admin1 code | 12 admin2 | 13 admin3 | 14 admin4
15 population | 16 elevation | 17 dem | 18 ★timezone | 19 modification date
```

## 3.2 建议的数据结构

```jsonc
// src/data/world-cities.json（按需懒加载，不进主 bundle）
{
  "countries": [
    { "code": "US", "name": "United States", "nameZh": "美国",
      "admin1": [
        { "code": "CA", "name": "California", "nameZh": "加利福尼亚州",
          "cities": [
            { "id": 5391959, "name": "San Francisco", "nameZh": "旧金山",
              "lat": 37.77, "lng": -122.42, "zone": "America/Los_Angeles", "pop": 827526 }
          ] } ] } ]
}
```

## 3.3 体积预算（**必须核**）

```
2.5 万城 × 约 95 字节 ≈ 2.4 MB 原始  →  gzip 约 450 KB
```

**处置**：
- **懒加载**：首次展开城市选择器时才 fetch，之后缓存
- **若 gzip > 800 KB**：改为**按国家分片**（`cities/US.json` 等），
  国家/州索引单独一个小文件
- **若仍过大**：优先保北美精度 —— 全球用 `cities15000`，
  **美国/加拿大/墨西哥 追加 `cities5000`**（目标市场，值得更细）

## 3.4 中文名范围（**已定：仅中国城市**）

**用户已拍板**：中文名不必全量，**中国城市有中文名就够了**。

| 范围 | 命名 |
|---|---|
| **中国城市**（现有 358 城） | **中文名**（保留现有策展数据） |
| **外国城市**（全球其余约 2.4 万城） | **英文名**（GeoNames 主名 / ascii 名） |
| 国家、州/省 | 英文名 |

**因此不做** `alternateNamesV2.zip`（数百 MB）的流式过滤 —— 构建脚本只下三个小文件。

### ⚠️ 由此产生的副作用（**记录在案，避免以后被当成 bug**）

> **中文用户搜「纽约」找不到 New York。**

这是**刻意接受的取舍**：目标是北美，英文名是主路径；而中文用户对自己居住城市的英文名
通常有认知（且出生地在国外时，多数人知道英文拼写）。

**搜索行为须明确**：

```
中国城市 → 匹配中文名（及拼音/英文别名若有）
外国城市 → 匹配英文名 + ascii 名（ascii 用于忽略重音，如搜 "Sao Paulo" 命中 "São Paulo"）
```

### 零成本可选（不做也不影响验收）

现有 22 个北美城市**已经带中文名**（洛杉矶/旧金山/纽约…）。
可以把它们**降级为"搜索别名"**（参与匹配、不作为主显示名）——
**零成本，且对中文用户友好**。

**但这只是加分项**，不做也完全符合本任务书。

## 5.1 ★ 新增断言的「牙口」要求（依 §8.6）

「其它」路径的测试用例**必须选在夏令时日期**：

```
✓ 有牙：纽约 1990-07-01（DST）→ 应得 13:30；若实现漏剥 DST 会得 14:30 → 断言必红
✗ 无牙：纽约 1990-01-15（无 DST）→ 剥不剥都是 14:30 → 测不出问题
```

**并建议仿照 `test-entry-consistency` 的做法，加一条"牙口自检"**：
断言该用例在「不剥 DST」时结果不同 —— 防止后人把日期改成冬天而**无声失去牙口**。

## 5.2 ★ 南半球与特殊时区必须入回归（**澳大利亚专项**）

澳洲是全球时区最"刁"的地方，**必须专门覆盖**（我方已实测，结果如下，请照此对表）：

| 难点 | 期望 |
|---|---|
| **半小时时区** ACST | `Australia/Adelaide` 1990-01 → UTC**+10.5** / 07 → **+9.5**（**不得四舍五入**） |
| **45 分钟时区** | `Australia/Eucla` → **+8.75** |
| **30 分钟夏令时**（全球唯一） | `Australia/Lord_Howe` 1990-01 → **+11** / 07 → **+10.5** |
| **南半球反向夏令时** | 1 月偏移 **>** 7 月偏移（悉尼 +11 / +10） |
| **历史夏令时** | `Australia/Brisbane` **1990-01 → +11**（昆州 1989–1992 曾行夏令时）<br>1988 / 1993 / 2000 的 1 月 → **+10** |

**真太阳时对表**（走"有经度"的城市路径）：

```
悉尼      1990-01-15 14:30 @151.21 → 校正 −55 分 → 13:35
阿德莱德  1990-01-15 14:30 @138.60 → 校正 −76 分 → 13:14
达尔文    1990-01-15 14:30 @130.84 → 校正 −47 分 → 13:43
豪勋爵岛  1990-01-15 14:30 @159.08 → 校正 −24 分 → 14:06   ← 夏令仅 +30 分
```

> **这些都不是我们实现的能力，是 IANA tzdata 带的** —— 我们只负责**取对**。
> 但**必须有用例证明我们取对了**，否则下一轮换实现时会无声退化。

# 七、一句话

> **简化方向完全正确** —— 让用户填经度本来就是设计错误，他们不可能知道，
> 填错了比不填更糟。**"选城市自动带时区" + "找不到就选时区"是对的。**
>
> **但要小心一件事**：「只选时区」不等于「不校正」。
> **它必须仍然剥掉夏令时** —— 否则夏天出生的人会**差 60 分钟**，足以改变时柱。
> 而正确做法我已经验证过了（§2.2）：**标准经线 = min(1月偏移, 7月偏移) × 15**。
>
> **另外提醒**：这个选择器要出现在 **5 处**，请**只写一个组件** ——
> 「某个入口忘了接」我们已经吃过两次亏了。
>
> **命名范围已定**：中国城市中文名、外国城市英文名（不做全量中文名）。
> **副作用记录在案**：中文用户搜「纽约」找不到 New York —— 这是**刻意取舍，不是 bug**。
