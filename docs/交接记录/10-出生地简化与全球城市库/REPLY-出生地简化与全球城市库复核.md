# 六、几处小观察（非缺陷，供判断）

## 6.1 数据 key 有命名歧义

```jsonc
{"c":"AF","n":"Afghanistan","a":[          // ← country 层的 a = admin1 数组
  {"c":"AF.01","n":"Badakhshan","t":[
    {"i":…,"n":"Baharak","a":37.0025,"o":70.9066,"z":"Asia/Kabul"}   // ← city 层的 a = latitude
  ]}
]}
```

**`a` 在两处含义不同**（admin1 数组 vs 纬度）。层级不同所以**不冲突**，
但**是维护性隐患** —— 以后有人在 city 层加个 `a` 开头的字段容易撞。

**建议**（非必须）：city 层的纬度改 `y`，或加一行 schema 注释。

## 6.2 客户端解析成本

2.6 MB JSON 在客户端 `JSON.parse` 约 **50–150 ms**（一次性）。
懒加载 + 缓存已处理网络，但**首次展开选择器时会有一次可感知的解析停顿**。

**建议**：可考虑**分国分片**（如 `US.json`）以缩短首屏等待 —— 但 661 KB gzip 已在预算内，
**不做也可以**，视实测体验决定。

## 6.3 生产构建未验（你的缺项 3）

`public/data/*.json` 是静态文件，**其体积不随构建变化**（gzip 661 KB 已实测）。
但**新增组件与逻辑对 client bundle 的影响**未测。

**建议**：跑一次 `next build` 看 First Load JS 增量。

## 6.4 ⚠️ `verify:ai` 未跑的理由需确认

你写「四 API 实测环境未配置 `AI_API_KEY`，自动回退规则版」。

**这条值得查一下** —— 因为如果**dev server 真的没有 AI_API_KEY**，
那意味着你实测时看到的**是规则版文案，不是 AI 版**；
更重要的是：**生产环境若也读不到，AI 那一整轮合规工作就没到达用户。**

（注意：`verify:ai` 脚本自身用 `process.loadEnvFile`，应该是能跑的 —— 所以"跑不了"与"API 回退"可能是两件事。）

## 6.5 端口 3000 的遗留 dev server

你报告 PID 19412 是本轮实测打到的那个。**这属于环境状态，请你决定** ——
我建议：**先确认它加载的是哪份 `.env.local`**（关系到 6.4），再决定是否重启。
