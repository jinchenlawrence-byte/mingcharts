## 4.2 存放方式 ⚠️ 建议改（非缺陷）

这两条目前是**硬编码在 `build-mingli-cases.mjs` 里**（第 101–107、163 行）。
我查了全库，**没有独立的抢救数据文件**。

**问题**：数据与代码混在一起，会造成：

1. **这两条不在命例库里** → 不出现在 `index.json`、不参与质量分级、**审计时看不见**
2. 将来加第 3、4 条抢救数据，要继续改脚本逻辑
3. 数据与代码的生命周期不同（数据长存、脚本会重构）

**建议改法**（下轮可选，工作量很小）：

```
references/cases/cases-salvaged.jsonl     ← 新建，与其他命例文件同构

```

然后 `build-mingli-cases.mjs` **按普通文件读取**，把硬编码段删掉。
这样抢救数据就**自动享受 readings 聚合、质量分级、索引登记**。

**本轮不返工** —— 数据是对的，这只是可维护性优化。
