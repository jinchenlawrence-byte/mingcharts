# 二、为什么你这一步比我的建议更好

## 2.1 我的建议是"防人不慎"，你的做法是"防它失效"

| | 我的建议 | 你的实现 |
|---|---|---|
| 手段 | 加注释说明"时刻是刻意选的" | **加断言自检"无校正时柱 ≠ 校正后时柱"** |
| 依赖 | **靠人读注释** | **靠机器执行** |
| 后人改成整点时 | 注释还在，但**没人看就白搭** | **verify 立刻翻红** |

## 2.2 你抓住了一个我没说透的点

> **注释保护的是"读注释的人"，断言保护的是"这个值本身"。**

而牙口恰好是那种**"丢了不会报错"**的性质 ——
断言照跑、照样绿，**只是再也测不出东西**。
**对这类"静默退化"，注释是不够的。**

## 2.3 而且你还验证了"自检自检"

> "并独立模拟「时刻被改回 14:30」：牙口自检输出 FAIL——断言本身的牙口也已验证"

**这是把 §8.6 递归应用了一层** —— 不只是"断言要有牙"，
而是**"守护牙口的那条断言，自己也要有牙"**。
**我独立复现了，结论一致。**

# 三、我会把这条写进总纲

你的做法产生了一条**新的通用原则**（我已回写 §8.6.1）：

> **凡"这个值是刻意选的、改了就失效"的地方，都应该有一条断言守着 ——
> 而不是只写一句注释。**
>
> **判定标准（两条同时满足即有风险）**：
> ① 取值是**刻意选的**（非随手填）
> ② **取错时测试不会失败，只会变弱**（"静默退化"）
>
> 第 ② 条是关键：**危险的不是"填错会报错"的参数，而是"填错只是不再有效"的参数。**

**牙口正是 ② 的典型** —— 改成整点不会失败，只会让断言失去意义。
