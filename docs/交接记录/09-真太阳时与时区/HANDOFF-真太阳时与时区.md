# 一、问题：实测证据

## 1.1 现状

`src/lib/solarTime.ts`：

```ts
/**
 * 真太阳时校正：按出生地经度相对【东八区中央经线 120°E】的分钟差平移。
 */
export function trueSolarOffsetMinutes(lng: number): number {
  return Math.round((lng - 120) * 4)   // ← 基准写死 120°E
}
```

**设计基准是北京时间**，所以在中国境内是正确的，**出了中国就全错**。

## 1.2 实测误差

| 出生地 | 经度 | 现行偏移 | **应为** | **误差** |
|---|---|---|---|---|
| 北京 | 116.4 | -14 分 | -14 分 | **0** ✅ |
| 上海 | 121.5 | +6 分 | +6 分 | **0** ✅ |
| 乌鲁木齐 | 87.6 | -130 分 | -130 分 | **0** ✅ |
| **纽约** | -74 | **-776 分** | +4 分 | **-13.0 小时** ❌ |
| **洛杉矶** | -118.2 | **-953 分** | +7 分 | **-16.0 小时** ❌ |
| **温哥华** | -123.1 | **-972 分** | -12 分 | **-16.0 小时** ❌ |

## 1.3 后果：时辰全错，多数情况**日期也错**

```
纽约    1990-07-01 14:30（未时）→ 现行算出 1990-07-01 01:34（丑时）
洛杉矶  1990-07-01 14:30（未时）→ 现行算出 1990-06-30 22:37（亥时）  ← 日期错
温哥华  1990-01-15 08:30（辰时）→ 现行算出 1990-01-14 16:18（申时）  ← 日期错
```

**日期一变，日柱必错；时辰一变，时柱必错；月初月末/年初年末还会影响月柱年柱。**

# 二、★ 正确算法（已实测验证，直接用）

## 2.1 公式

```
真太阳时 = 当地钟表时刻 + (出生地经度 − 当地实际UTC偏移小时数 × 15) × 4 分钟
```

**关键**：「当地实际 UTC 偏移」**必须从 IANA 时区数据库取历史值**，
不能套用"现在的"偏移 —— 因为 **夏令时规则是历史变动的**。

```ts
const offsetMinutes = Math.round((lng - utcOffsetHours * 15) * 4)
```

## 2.2 ★ 取历史偏移的实现（含符号陷阱）

```ts
/** 取指定 IANA 时区在【某一历史时刻】的实际 UTC 偏移（小时，东正西负） */
function getUtcOffsetHours(
  zone: string, y: number, m: number, d: number, h: number, mi: number
): number {
  const utcGuess = Date.UTC(y, m - 1, d, h, mi)
  const dtf = new Intl.DateTimeFormat('en-US', {
    timeZone: zone, hour12: false,
    year: 'numeric', month: '2-digit', day: '2-digit',
    hour: '2-digit', minute: '2-digit', second: '2-digit',
  })
  const o: Record<string, string> = {}
  for (const p of dtf.formatToParts(new Date(utcGuess))) o[p.type] = p.value
  const asUTC = Date.UTC(+o.year, +o.month - 1, +o.day, +o.hour % 24, +o.minute, +o.second)
  return (asUTC - utcGuess) / 3600000
  //      ^^^^^^^^^^^^^^^^^^ ★ 是 asUTC − utcGuess
  //      写成 utcGuess − asUTC 会得到【相反符号】：
  //      Asia/Shanghai 会返回 UTC−8（应为 +8），北美会返回正偏移 → 全盘皆错
}
```

> **这个符号我第一版写反了。** 自检方法：**Asia/Shanghai 1990-01 必须返回 +8**，
> **America/New_York 1990-07 必须返回 −4**。见 §六 回归测试。

## 2.3 已实测验证的结果（请照此对表）

| 出生地 | 当地钟表时刻 | 实际偏移 | 正确校正 | **正确真太阳时** | 现行（错） |
|---|---|---|---|---|---|
| 纽约 | 1990-07-01 14:30 | UTC−4 | −56 分 | **13:34（未时）** | 01:34（丑时） |
| 纽约 | 1990-01-15 14:30 | UTC−5 | +4 分 | **14:34（未时）** | 01:34（丑时） |
| 洛杉矶 | 1990-07-01 14:30 | UTC−7 | −53 分 | **13:37（未时）** | 06-30 22:37（亥时） |
| 温哥华 | 1990-01-15 08:30 | UTC−8 | −12 分 | **08:18（辰时）** | 01-14 16:18（申时） |
| 北京 | 1990-01-15 14:30 | UTC+8 | −14 分 | **14:16（未时）** | 14:16 ✓ |
| 上海 | 1990-01-15 14:30 | UTC+8 | +6 分 | **14:36（未时）** | 14:36 ✓ |

## 2.4 依赖选择

**两条路都可以**：

| 方案 | 说明 |
|---|---|
| **A. 用 `Intl`（零依赖）** | 上面 §2.2 的实现即可。Node ≥ 13 自带完整 ICU/tzdata |
| **B. 用 `luxon`** | `DateTime.fromObject({...}, {zone})` 直接拿 `.offset`，更省心，但要加依赖 |

**推荐 A**（零依赖、已验证），若你更倾向 B 也可以，**但须自己验证符号方向**。

## 2.5 ★ 顺带修好的：中国 1986–1991 夏令时

**中国在 1986–1991 年实行过夏令时**（4 月中旬–9 月中旬，+1 小时），
而现行代码**完全忽略 DST** → 那几年夏天出生的中国用户**也差 1 小时**。

```
北京 1988-07-01 14:30
  正确（tzdata：当时 UTC+9）→ 13:16
  现行（忽略 DST）        → 14:16     ← 差 1 小时
```

**小时差在时辰边界附近就会改变时柱。** 用 tzdata 后**自动修好**。

# 五、UI：出生地与时区选择

## 5.1 交互设计

```
出生地
  ┌──────────────────────────────────────┐
  │ 🔍 搜索城市（中文/English）            │
  └──────────────────────────────────────┘
  → 选中后显示：纽约 · New York, USA
                经度 -74.0  时区 America/New_York  [可修改]

  ── 找不到？手动输入 ──
  经度 [ -74.0 ]   时区 [ America/New_York ▾ ]
```

## 5.2 ★ 关键 UX 原则

> **用户只需要填「钟表上的时间」。**
> **他不需要知道当时有没有夏令时 —— 那是软件的责任。**

- 用户填「1990-07-01 14:30」= 出生证/家人记忆里的钟表时间
- 软件根据 `时区 + 日期` **自动判断当时是否 DST**（用 tzdata）
- **不要问用户"你填的是标准时还是夏令时"** —— 他答不出来，答错更糟

## 5.3 边界情况（须处理或至少提示）

| 情况 | 处理 |
|---|---|
| **夏令时切换的"不存在时刻"**（春季跳表，02:30 不存在） | 用库的解析结果，并在 UI 提示"该时刻处于夏令时切换点，已按 X 处理" |
| **夏令时切换的"重复时刻"**（秋季回拨，01:30 出现两次） | 同上，提示 |
| 用户没选时区 | 默认 `Asia/Shanghai`（现有行为），**但要显式显示默认值**，不能静默 |

## 6.1 符号自检（**最容易踩的坑**）

```

America/Vancouver    1990-01-15  →  -8
```

## 6.2 真太阳时用例（照 §2.3 对表）

```
纽约   1990-07-01 14:30 @ -74.0     → 13:34（未时）
纽约   1990-01-15 14:30 @ -74.0     → 14:34（未时）
洛杉矶 1990-07-01 14:30 @ -118.2    → 13:37（未时）
温哥华 1990-01-15 08:30 @ -123.1    → 08:18（辰时）
北京   1990-01-15 14:30 @ 116.4     → 14:16（未时）
上海   1990-01-15 14:30 @ 121.5     → 14:36（未时）
北京   1988-07-01 14:30 @ 116.4     → 13:16（未时）  ← 中国夏令时
```

## 6.3 ★ 端到端断言（最有价值的一条）

**不只测偏移，要测"四柱"**：

```
断言：纽约 1990-07-01 14:30 出生的命盘，
      其时柱 ≠ 用 01:34 推算出的时柱
（防止有人改了偏移却没接进排盘链路）
```

**即：必须验证修复真的传导到了 `paipan()` 的输出。**
