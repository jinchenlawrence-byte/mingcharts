# 二、⚠️ 但三个北美案例「无牙」—— 量化证据

## 2.1 什么是「有牙」

一条断言要能发现"某入口漏接时区"，**它用的出生时刻必须满足**：

> **校正前与校正后落在【不同的时辰】。**

时辰是 120 分钟一轮。偏移 Δ 分钟时，出生时刻 T 只有在
**`T 相对时辰起点不足 |Δ| 分钟`** 时才敏感 —— 否则校正前后是同一个时辰，结果相同。

## 2.2 实测（我逐案例验）

```
用例                      正确(带偏移)            漏接(偏移0)             有无牙
纽约 14:30 (脚本案例)      庚午 壬午 丁卯 丁未      庚午 壬午 丁卯 丁未      无牙 ✗
纽约 13:10 (回传验证用)    庚午 壬午 丁卯 丙午      庚午 壬午 丁卯 丁未      有牙 ✓
洛杉矶 14:30 (脚本案例)    庚午 壬午 丁卯 丁未      庚午 壬午 丁卯 丁未      无牙 ✗
温哥华 08:30 (脚本案例)    己巳 丁丑 庚辰 庚辰      己巳 丁丑 庚辰 庚辰      无牙 ✗
乌鲁木齐 14:30            己巳 丁丑 庚辰 壬午      己巳 丁丑 庚辰 癸未      有牙 ✓
北京 1992 09:00           壬申 戊申 癸亥 丙辰      壬申 戊申 癸亥 丁巳      有牙 ✓
```

**→ 脚本里三个北美案例全部无牙，只有乌鲁木齐与北京保住牙口。**

## 2.3 关键：你自报的「有牙验证」用的时刻**不在脚本里**

回传 §二-2 写：

> ```
> 纽约 1990-07-01 13:10：旧 geo(偏移0) 时柱 丁未 ｜ 正确(-56) 时柱 丙午 → 横向比对必红
> ```

**13:10 确实有牙（我已验证）。但脚本 `CASES` 里的纽约是 14:30 —— 那个时刻无牙。**

**所以"验证过有牙"和"脚本里实际用的"不是同一个时刻。**
（我理解这不是有意：13:10 是从我复核回执 §3.2 抄来的例子，而脚本案例沿用了更早的 14:30。）

## 2.4 影响

- **不是"假测试"** —— 整体断言仍靠乌鲁木齐/北京具备牙口，`ENTRY_CONSISTENCY_PASS` 有意义
- **但覆盖有盲区**：若将来**北美路径单独坏掉**（例如北美城市数据的 `zone` 字段被改错、
  或某个入口对北美分支特殊处理），**三个北美案例都不会报**
- **而北美正是这一整套修复的目的** —— 头号案例没有牙，可惜

## 2.5 修法（很小）

```js
// 把纽约案例的时刻改到「时辰起点后不足 56 分」的位置
['纽约·城市', { ..., hour: 13, minute: 10, ... }]   // 13:10 → 校正后 12:14（午时）→ 时柱必变

// 并可再补一条边界案例：
['纽约·边界', { ..., hour: 13, minute: 30, ... }]   // 13:30 → 12:34 → 仍是午时边界样本
```

**并建议加一句注释说明"案例时刻是刻意选的"，防止以后有人"顺手改成整点"把牙口弄丢：**

```js
// ★ 时刻是刻意选的：须落在「时辰起点 + |偏移|」之内，否则校正前后同时辰，
//   断言对该入口失去牙口（见 REPLY §二）
```

## 2.6 顺带：一条可复用的判据

> **测试用例不能"随便挑一个时刻"，必须落在【判别边界内】。**
>
> 对"偏移 Δ 分钟的修正"这类改动，**判别边界**是：
> `出生时刻相对时辰起点 < |Δ|`。
> 选在边界外的时刻，**断言恒绿，等于没测。**
