# 三、一个必须记下的局限（不阻断）

② 的判据是**源码结构**，不是**渲染结果**：

```js
src.includes('getLiunian(sx, YEAR)')                 // 关系从哪来
src.includes('FAN.filter((r) => r.ln.relation === rel)')  // 分组怎么写
+ 页面里不得出现生肖字（防写死）
```

**能抓住的**：改年份、改数据源、写死名单（三次牙口已证明）。
**抓不住的**：写法正确但逻辑写反（例如把 `=== rel` 改成 `!== rel`）。

离线环境无法渲染 React 服务端组件，所以这条只能到结构层。
**风险可接受**（逻辑反转属于明显错误，且线上抽样会立刻看出分组不对），
但**不要以为它等于"渲染结果已验证"**——记在这里。

# 四、内容上值得肯定的一处

任务书只要求「两个日期都要写清」，实际写成：

```
★ 时间边界有两个，别混用：民俗的过年是春节 1 月 26 日（2028-01-26）
  （安太岁、生肖轮替按此）；命理的年柱切换是立春 2 月 4 日 15:31（2028-02-04）
  立春是时刻不是整日——当天 15:31 之前出生仍按丁未年算，之后才是戊申年。
```

**「立春是时刻不是整日」这句是本轮最有价值的一句文案**——
2028 的两个边界相差 9 天（2027 只差 2 天），这句话正好解释了为什么很多人算错属相。
