# 二、提取方法（因为没有表格，实际采用的规则）

命例表的版面上是 4 竖列（年／月／日／时），姓名官衔与年月干支挤在同列。GLM-OCR 把每列识别成一个或多个 `vertical_text` 块，块内用换行分隔条目。我最终的提取规则（`temp/extract_cases_v7.py`）：

1. 只取宽度 40–150px 的竖排块（排除宽条文块、页眉页脚）；
2. 逐行匹配，**保留恰好含 2 个合法干支、且干支后紧跟非空中文（人物/官衔）的行**；
   例：`戊子 乙酉元戎` → 年柱戊子、月柱乙酉、官衔元戎；
3. 日柱、时柱取自该页条文标题 `六X日X時斷`（正则从页面任意块提取）；
4. 显式排除 `X日Y時` 模式的行（那是条文标题，不是命例）及诗诀关键词。

**这个方法的先天漏损**：
- 只提取了"年月干支 + 官衔"在**同一行**的命例；凡年月分列两两块、或干支与姓名错开的，全部漏掉；
- 日柱/时柱依赖页面标题被 OCR 正确识别——31 条因此日时为空。

## 4.3 历史交叉验证的"期望值"本身没有溯源——2 条存疑可能误判

我在脚本里内置的人物生年表（毛惇元≈1520 庚辰、徐錦≈1500 庚申等）**是凭知识估计的，未查权威史料**。

这两条的可靠处理方式应是：先查可靠来源确认毛惇元/徐錦生年，再决定是否存疑；在此之前标签措辞宜降为"待核实"。请确认是否照此修正。
