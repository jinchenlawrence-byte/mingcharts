# 一、三重证据（可复算）

## 证据 1：五鼠遁 —— 证明"日/时柱推断"是对的

八字硬规则：**时干由日干唯一确定**（甲己还加甲，乙庚丙作初…）。

对 88 条四柱俱全者检验：

| 检验 | 合法率 |
|---|---|
| **日/时柱（原样）** | **87/88 = 99%** |

**99% 意味着什么**：时柱来自小节标题（如「甲申日乙丑時」取"乙丑"），日柱也来自同一标题（取"甲申"）。
两者能通过**独立的历法规则**互证 —— 这就把"推断"和"编造"彻底区分开了。
**§4.2 的疑问到此可以结案：符合红线，且是本次交付里质量最高的部分。**

## 证据 2：五虎遁 —— 证明"年/月柱"被颠倒

八字硬规则：**月干由年干唯一确定**（甲己之年丙作首，乙庚之岁戊为头…）。
即：`月干起 = (年干序 % 5) × 2 + 2`（寅月起），逐月递进。

对 88 条检验：

| 读法 | 合法率 |
|---|---|
| 按你现在的「年=M1，月=M2」 | **19/88 = 22%** |
| **按「年=M2，月=M1」互换** | **61/88 = 69%** |

例（SMTB-0003，卷八页13）：
```
你的数据:  年=戊子  月=乙酉
五虎遁:    戊年 → 正月甲寅…（戊年不存在"乙酉"月）  ✗ 历法上不可能
互换后:    年=乙酉  月=戊子 → 乙年正月戊寅…戊子=十一月  ✓ 合法
```

# 二、逐条回答你的 5 个问题

## §4.1 「119 条算合格交付还是应返工？」→ **返工，但不是换工具**

**判断：GLM-OCR 没问题，问题在你的解析规则。**

证据：五鼠遁 99% 通过，说明**它认的字是对的**；而且它返回里带了 **`bbox_2d` 坐标**
（我看了 `06056484.cn_chunk_00_ocr.json`，每个块都有 `bbox_2d/label/native_label`）。

**所以你有比"文本行启发式"强得多的武器没用**：既然有坐标，**表格列序应该由几何决定，而不是由文本行的顺序猜**。
这正是 119 条覆盖率低的根因——你现在只捞到了"年月干支+官衔挤在同一行"的命例。

**建议返修方案（不重跑 OCR）**：
1. 从已保存的 7 份 `*_ocr.json` 里取 `layout_details[i]`（第 i 页的块列表）
2. 用 `bbox_2d` 做**列聚类**：x 区间相近的块归为同一列（竖排，列序按 x 从大到小）
3. 结合小节标题块（`native_label` 为 `vertical_text` 且内容含「X日Y時」）的 **y 位置**，
   判定每个命例块归属哪个小节
4. 这样应能**捞回现在漏掉的大部分命例**（现只 119 条，任务书预期"数百造"）

> **不建议**改用 GLM-4V-Flash 重跑：那是 604 次调用，且它的表格能力并不比 GLM-OCR 强。

# 四、可直接复用的校验代码

```python
GAN='甲乙丙丁戊己庚辛壬癸'; ZHI='子丑寅卯辰巳午未申酉戌亥'
gi=GAN.index; zi=ZHI.index

def wuhu_ok(nian_gz, yue_gz):
    """五虎遁：月干由年干定。合法返回 True"""
    s = (gi(nian_gz[0]) % 5) * 2 + 2          # 寅月起月干
    o = (zi(yue_gz[1]) - 2 + 12) % 12 + 1     # 寅=1 .. 丑=12
    return GAN[(s + o - 1) % 10] == yue_gz[0]

def wushu_ok(ri_gz, shi_gz):
    """五鼠遁：时干由日干定。合法返回 True"""
    s = (gi(ri_gz[0]) % 5) * 2                # 子时起时干
    o = zi(shi_gz[1])
    return GAN[(s + o) % 10] == shi_gz[0]
```

**注意**：这两个函数只依赖干支本身，**不需要任何外部数据**，可作 CI 级别的硬门槛。
