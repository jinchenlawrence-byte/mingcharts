# 二、逐条回应

## 2.1 紫微：构建参数收为单一事实源（§2.3）

[ziwei.ts](../../../src/lib/ziwei.ts)：

- `ZwChart` 新增两字段：`ziweiDateStr`（构建 iztro 盘的公历日期，含校正＋晚子时推进）、`ziweiTimeIndex`（时辰索引）。
- **入口一** `paipanZiwei`：真太阳时校正后，若 `hour === 23`，用 `Date.UTC` 做日历日 +1；timeIndex 保持 0；两参数存入返回的 chart。
- **入口二** `analyzeZiwei`：改为 `astro.astrolabeBySolarDate(chart.ziweiDateStr, chart.ziweiTimeIndex, …)`，并留禁止注释——不得再从 `chart.input` 推导。

## 2.2 晚子时推进的一个同族边界（查证中发现，已随修）

任务书 §2.4 只写了「校正后 hour=23 → +1」。实测发现**负偏移把当地 0:xx 拉回前一日 23:xx** 的情形（重庆 0:00−54 → 前日23:06；纽约 0:00；成都 0:30−64 → 前日23:26）：

- 旧入口一：不推进 → 用户看到的盘建在**前一日**；
- 旧入口二：用 input 当日 → 大限 ganZhi/四化出自当日盘，但 buildPeriod 的**星曜**映射到用户所见的前一日盘——ganZhi 与星曜来自两张盘，是 P0 报告之外的同型隐蔽形态。
- 修复后：23:06/23:26 按晚子时推进回当日，盘（当日）与运限（读同一 chart）完全归一。

这不是超出拍板范围：推进规则的触发条件始终是「校正后小时 = 23」，与本地钟点无关。

## 2.3 日运归日（§3.2）

[daily.ts](../../../src/lib/daily.ts) 新增 `dailyDateInZone(zone, now?)`：Intl 取该时区墙钟年月日时；`hour >= 23` 用 Date.UTC +1；非法 zone 经 isValidZone 降级 DEFAULT_ZONE。`liuRiOf` 的 12:00 固定构造未动（职责分离）。
