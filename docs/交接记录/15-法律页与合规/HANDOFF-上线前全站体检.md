# 一、六类扫描（逐类给出方法、判据、处置）

## 2.1 metadata 齐全性

**扫什么**：`src/app/**/page.tsx` 是否都有 `export const metadata`

```powershell
# 列出所有 page.tsx 及其是否含 metadata
Get-ChildItem src\app -Recurse -File -Filter page.tsx | ForEach-Object {
  $has = Select-String -Path $_.FullName -Pattern 'export const metadata' -Quiet
  "{0,-46} {1}" -f $_.FullName.Replace("$PWD\src\app\",''), $(if ($has) { '有 metadata' } else { '★ 缺' })
}
```

**★ 特别注意**：`title` / `description` 里若有**硬编码的价格或字数**（如"万字详批"），
要与实际一致 —— 这类文案最容易与实际脱节。

**处置**：缺 metadata 的**补上**（从页面实际内容写，不要空话）✓

## 2.2 ★ 红线词与依据分级

**扫什么**：用户可见文案里是否出现禁用断言词（「必定」「务必」「势必」「一定会」等）

**★★ 判据必须复用现有的**，不得另写：

```
· 找到 checker 模块（scripts/test-checker-accept.mjs 引用的那个）里的判据常量
· 用它扫 src/ 全量 .ts/.tsx 的【用户可见字符串】
★ 若判据不可导出，先报告，不要自己抄一份 ✗
```

**处置**：
- 命中且**确实在用户可见处** → **修** ✓（改为有条件的表述）
- 命中但在**注释 / 变量名 / 测试用例**里 → **不修**，但列出来说明 ✓

## 2.3 ★★ 占位符 / TODO / 调试残留

**扫什么**：

```powershell
# ① 占位符与待办
Get-ChildItem src -Recurse -File -Include *.ts,*.tsx | Select-String -Pattern 'TODO|FIXME|XXX|待补|待定|placeholder|Lorem|TBD|\[.*\]' |
  Where-Object { $_.Line -notmatch '^\s*(//|\*|/\*)' }   # 排除注释
# ② 调试残留
Get-ChildItem src -Recurse -File -Include *.ts,*.tsx | Select-String -Pattern 'console\.(log|debug|warn)|debugger|alert\('
# ③ 假数据 / 模拟值
Get-ChildItem src -Recurse -File -Include *.ts,*.tsx | Select-String -Pattern 'MOCK_|mock|dummy|fake|测试用|example\.com'
```

**★ 判据**：
- **用户可见文案**里有占位符 → **修** ✓
- **服务端日志**里的 `console.error` → **不修** ✓（那是必要的错误日志）
- **`console.log` 调试输出** → **删** ✓
- **`example.com` / `your_xxx_here`** → 若在 `.env.example` 里**保留** ✓；在别处 → **修** ✓

## 2.4 ★★★ 「承诺了却不存在」的功能描述 —— **本任务的重点**

**扫什么**：全站**面向用户的文案**里，凡是说"你可以……"「在……里可以……」的，
**逐条核对那个能力是否真的存在**。

**扫这些位置**：

```
· src/app/**/page.tsx 的 JSX 文案与 metadata.description
· src/app/**/*Content.tsx（页面主体）
· src/components/*.tsx（尤其按钮、引导、帮助文案）
· src/app/pricing/page.tsx（最可能出问题 —— 它描述"买了能得到什么"）
· 任何 "Account Settings" / "设置" / "你可以" / "支持" / "随时" 字样附近
```

**★ 判据（三步）**：

```
① 找到文案里的【功能承诺】—— 动词 + 宾语 + 位置，如"在账户设置里取消订阅"
② 去代码里找【兑现点】—— 该路由/组件/API 是否存在
③ 三者对齐才通过：
     文案说的地方  =  代码里存在的地方
     文案说的能力  =  代码里实现的能力
     ★ 若只有文案没有代码 → 报告，并给出【两种修法】让我选：
         (a) 删掉/改写文案（诚实 ✓）
         (b) 实现该能力（若成本低且你判断值得）
   ❌ 不要自行二选一 —— 那涉及产品决策
```

**★★ 典型案例（我方已发现的、已修的）**：

```
位置：terms.md §6.1（原文）
文案：「You may cancel your subscription at any time through:
       Online (recommended): Account Settings → Subscription → Cancel Subscription」
实际：该界面【不存在】✗（会员功能尚未开放）
处置：改为"仅邮件取消"＋声明订阅尚未开放  ← ★ 这是正确修法的样板
```

**★★★ 请按这个思路，把全站同类问题都找出来。**

## 2.5 死链 / CTA 可达性

**扫什么**：站内链接与按钮指向的路由是否存在

```powershell
# ① 抓出所有站内链接
Get-ChildItem src -Recurse -File -Include *.tsx | Select-String -Pattern 'href="/[^"]*"' |
  ForEach-Object { $_.Matches } | ForEach-Object { $_.Value } | Sort-Object -Unique
# ② 与 src\app 下的实际路由对照
Get-ChildItem src\app -Recurse -File -Filter page.tsx | ForEach-Object {
  $rel = $_.FullName.Replace("$PWD\src\app\",'').Replace('\page.tsx','')
  if ($rel -eq 'page.tsx') { '/' } else { '/' + ($rel -replace '\\','/') }
}
```

**★ 判据**：链接指向的路由**存在** → ✓；不存在 → **报告，并注明是"该建页面"还是"该改链接"** ✗

**★★ 注意**：`/terms` 与 `/privacy` 若**尚未建**（另一份任务书在做），
**列为"已知、由另一任务负责"，不要重复修** ✓

★ pricing-accept 已有"裸数字金额"断言 —— 先确认它覆盖了哪些目录
  若它只扫 src/，那已经够了；若只扫部分，请报告缺口 ✗
★★ 另外要查【非价格但会脱节的数字】：

   · "每月 X 次" —— 是否有配额这回事？
   · 日签"180 条" / 会员"六大权益" 之类
   ★ 判据：文案里的数字，必须在代码里有对应的常量或可验证的来源
   → 查不到来源的，报告（可能是旧的、或从未实现的）

     ★★ 白名单每项必须注明【由哪个任务负责】，且【该任务完成后必须移出白名单】

```

     抓不到"链接指向了存在但内容错误的页面"✗

★ 二、牙口必须用【文本不变、行为变坏】的注入 —— 例如：
     删掉某个 page.tsx 的 metadata 一行（其余不动）→ ① 必须精确翻红
     ★ 注入前【先确认注入有效】（打出改动后的实际行内容），确认失败即中止
     ★ 恢复后必须复绿
     ❌ 不要用"把整段注释掉"这种【文本注入】—— 那只能验出静态检查
```
