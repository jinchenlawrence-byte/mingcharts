### ★ 第 2/3 步的起点实测（2026-10-08，我方查公共 DNS）

```
A / AAAA / MX / TXT / CNAME —— 【全部为空】
查询各类型时只返回一条 SOA：
    PrimaryServer  = matt.ns.cloudflare.com    ✓ 确认 Cloudflare 托管
    Administrator  = dns.cloudflare.com        ✓ Cloudflare 管理
    DefaultTTL     = 1800
→ ★ 结论：DNS 完全空白，【加 Zoho 记录时不会有同名冲突】✓

```

**★ 我方自省（又一次自己的方法出错）**：
我第一次读到"各 1 条"就以为**已有记录、需注意冲突** ✗ ——
**实际那 1 条是解析器附带的权威段 SOA**，不是真记录 ✓
**→ 教训："计数非零"不等于"内容存在"；拿到 1 个结果要【打印它是什么】再下结论** ✓
（与我给 TraeCode 立的 §8.6.5 "判据要覆盖全部实质内容"、§8.6.8 "计数是影子" 是同一条）

### ★★ Cloudflare 特有的三个坑（第 3 步加记录时会遇到）

```
① 橙色云朵（Proxy）只对 A / AAAA / CNAME 有意义
   · 我们要加的 MX / TXT（SPF/DKIM/DMARC）【不受影响】✓
   · ★ 但若 Zoho 要求加指向其服务器的 A 或 CNAME，
     必须设为【DNS only（灰云）】✗ 否则邮件流量会被 Cloudflare 代理，连不上

② TXT 值【不要自己加引号】
   · Cloudflare 对 TXT 的处理与部分注册商不同；
     直接粘贴 Zoho 给的值即可，加了引号反而会变成值的一部分 ✗

③ ★ 记录冲突：加之前先看有没有同名的旧记录
   · 尤其 MX 与 TXT(@) —— 有旧的先删掉，不要并存
```

  它的认证域是 gmail.com、发信域是你的域名 → 不对齐 → DMARC 过不了 ✗

**★ 为什么可以用 `p=none` 起步**：

```

       报告会发到 rua 指定的邮箱（hello@）✓
确认一切正常后，再考虑收紧到 p=quarantine → p=reject
★ 所以：p=none 现在加是安全的，不必等测试完
```

**★ 至此 4 条记录齐备**：MX（收信）· SPF（发信授权）· DKIM（签名）· DMARC（策略）✓

**★ 关于顺序**：`p=none` 不会拒信，所以**放在测试之后补也完全没问题** ✓
