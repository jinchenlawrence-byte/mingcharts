# 二、❌ 城市五行：模型退化（**根因在我的规格**）

## 2.1 实现本身是对的

必须先说清楚：**你完全按我的规格实现了。**

- `bearingFromOrigin()` 用了 `cos(lat)` 修正经度压缩 —— **方法正确** ✓
- `directionWuxing()` 按 45° 分八方 —— ✓
- `reason` 逐条写明「主五行X：位于中心点X方（方位角约X°）…；次五行Y：…（地气物产取象，属产品设定）」 —— ✓
- 86 城自检一致、不一致则 `exit 1` —— ✓

**问题不在实现，在我的规格。**

## 2.2 但结果退化了

我统计了 86 城的主五行分布：

```
木  53 城   62%  ███████████████████████████████
金  12 城   14%  ███████
火  11 城   13%  ██████
土  10 城   12%  ██████
水   0 城    0%          ← ★ 一个都没有
```

**按方位角分区：**

| 方位 | 城市数 |
|---|---|
| 北(水) | **0** |
| 东北(土) | 7 |
| 东(木) | 32 |
| 东南(木) | 22 |
| 南(火) | 11 |
| 西南(土) | 1 |
| 西(金) | 9 |
| 西北(金) | 4 |

## 2.3 根因

**「方位五行」在命理里是「相对某个中心的方位」，而中国所有主要城市都在 103°E 以东。**
所以：

- 东 + 东南 = **54 城（63%）判「木」**
- 「北」扇区（正北 ±22.5°）在中国境内 **没有城市**（那里是蒙古／西伯利亚）
  → **「水」永不可达**

## 2.4 后果：功能性缺陷

**「水」城市数为 0，意味着任何喜用含水位的命主，都推荐不出水城。**

具体到产品：

| 日主 | 关键类别对应五行 | 后果 |
|---|---|---|
| **木日主** | 贵人之城 = 印 = **水** | **0 候选** |
| **火日主** | 贵人之城 = 印 = **木**（有 53 城，过载） | 候选严重偏斜 |
| 身弱的水日主 | 喜用 = 金/水 | 水城 0 候选 |

**这不是"区分度不够"，是"某些类别直接取不到候选"。**

## 2.5 我的规格错在哪

我在任务书 §3.2 写的是：

> 主五行 `wx` 改用「方位五行」…**以中国地理中心为原点**…

**这个前提是错的。** 「方位五行」的本义是**方位对人的影响**（相对个人），
**不是城市的固有属性**。把"城市相对中国中心的方位"当成城市的五行标签，
必然得到退化分布——因为中国城市本就在地理中心的东半边。

**更合理的模型（供你判断，不强制）：**

| 概念 | 应该是什么 | 当前实现 |
|---|---|---|
| 城市的**固有**属性 | **地气**（地理/物产/产业特征），属**产品设定** | 现为 `wx2` |
| **方位**（相对个人） | **相对命主出生地的方位**，有命理依据 | 已有 `direction` |

即：**把 `wx`（主）与 `wx2`（次）的角色对调** ——
地气作城市固有五行（明确标为产品设定），方位作**对个人的相对判断**（已有 `direction` 承载）。

> 我在原任务书里给过口子：「若你认为『物产取象』更合适，也可以 —— 但必须统一用一套」。
> **现在看来那个口子才是对的方向。**

**你也可以提出更好的方案。** 关键是：**五行分布不能退化到某一类取不到候选。**

# 四、回答你 §五 的三个问题

## Q1 `dayun` 权重：是否降权或仅展示？

**答：应降权——我倾向「仅作展示，不参与总观感」。**

理由三条：

1. **它是唯一依据等级为 `产品设定` 的维度**，与 6 个典籍维度**等权参与**，
   等于把自创指标与典籍判据**等价呈现**——这正是《验收标准与红线》红线 3 要防的
2. **它是时变的**：同一对情侣，不同年份算出的合婚总观感会变。
   合婚"基础契合度"不该逐年漂移
3. 它描述的是**当前节奏**（临时状态），不是**双方根本契合度**（长期属性）

**建议**：`dayun` 卡片**照常展示**（有参考价值），但**不进入 `overall` 的比例计算**；
或在卡片上明确标注"仅示当前节奏，不参与总评"。

## Q2 `yearZodiac` 是否加「生肖不合 ≠ 不能结婚」？

**答：应该加。**

生肖合婚在**民间影响极大**，是**最容易被误用**的维度——
现实中确实有人因为"生肖相冲"而拆散姻缘。

加这一行小字**既是诚实，也是保护用户**：
- 它已标 `民俗`（依据等级最低）
- 但用户未必理解徽章含义，**一句直白的话比一个徽章更有效**

## Q3 城市次五行在合婚报告中是否也需同步展示来源？

**答：分两层。**

- **短期**：凡展示城市五行处，**都应带来源标注**（
  "主五行（方位，可复算）／次五行（地气取象，产品设定）"），保持一致。
- **但更重要的是先解决 §二**：现在 0 水城，
  **两套来源都标全了，也解决不了"推荐不出水城市"**——那是模型问题，不是标注问题。
