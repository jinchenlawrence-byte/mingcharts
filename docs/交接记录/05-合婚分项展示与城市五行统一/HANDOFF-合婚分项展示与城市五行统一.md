# 一、背景：为什么要改

## 1.1 现状问题（前序审核发现）

`src/lib/hemun.ts` 现在是：

```js
let score = 60                    // 基础分
// ... 七个维度各自 delta
const totalScore = Math.max(0, Math.min(100, Math.round(score)))
const grade = totalScore >= 85 ? '上等良缘'
            : totalScore >= 75 ? '上等婚配'
            : totalScore >= 65 ? '中上等婚配'
            : totalScore >= 55 ? '中等婚配·宜多经营' : ...
```

**三个问题**：

1. **基础分 60 压缩了有效区间** —— 七维度全中性也拿 60 分（"中等婚配"）；
   到"下等"须净亏 5 分以上 → **评级普遍偏高，有讨好用户观感**
2. **`86 / 100` 是伪精确** —— 命理合婚本无"打分"传统，
   给一个精确到个位的分数，反而显得不可信
3. **掩盖了维度的依据差异** —— 七个维度里，
   「日支夫妻宫」有典籍依据，而「年柱生肖」「纳音」是民俗/古法。
   **混在一个总分里，等于把民俗和命理等价呈现**

## 1.2 用户决定

> **改成分项展示。**

# 二、★ 主任务：合婚改分项展示

## 2.1 目标

## 2.2 数据结构改动

```ts
export type DimBasis = '典籍' | '古法' | '民俗' | '产品设定'

export interface HemunDimension {
  key: string
  name: string
  delta: number          // 保留：仅供内部排序/调试，不做主展示
```

## 2.4 总观感：改用「维度分布」而非「分数求和」

**不再用 `60 + Σdelta` 定等级。** 改为按维度分布给总观感：

```ts
const ji  = dims.filter(d => d.level === '吉').length
const ji2 = dims.filter(d => d.level === '忌').length
const n   = dims.length          // ⚠️ 不写死 7 —— 若拆了 year，这里会变成 9

// 建议口径（按比例，不写死个数）
const r = ji / n
const overall =
  r >= 0.7 && ji2 <= 1 ? '互补性强，契合度高' :
  r >= 0.55            ? '整体协调，长处在多' :
  ji2 / n >= 0.55      ? '差异较大，需用心经营' :
  ji >= ji2            ? '吉多于忌，宜多沟通' :
                         '各有长短，重在磨合'
```

**前端主展示改为这句话，不再显示 `86 / 100`。**

**`totalScore` 字段**：可保留（供排序/调试），但**前端不得作为主展示**；
如需显示，须**降级为小字并标注「算法内部参考，非命理定论」**。

> ⚠️ **维度数不要写死。** 若按 §2.3.1 方案 A 拆了 `year`，
> 维度数会从 7 变成 9。上面的比例式写法对两者都成立。

# 三、城市五行：统一取象标准

## 3.1 问题

`src/data/geo-cities.json` 的 86 城，`wx`（主五行）**混用两套不相容依据**：

| 体系 | 依据 | 北京应判 |
|---|---|---|
| **方位五行**（命理正统） | 东木/南火/西金/**北水**/中土 | **水** |
| **地气物产取象**（现代发明） | 皇城=土、煤铁=金、港口=水 | **土** ← 实际用了这个 |

实例：大连按"在北"和"港口"都判水（自洽），**北京按方位该是水却判了土** —— 标准不一致。

> 声明（上一轮已加）解决了**合规**问题，但**内部不一致**还在。

## 3.2 统一方案（建议，若你有更优方案请提出）

**主五行 `wx` 改用「方位五行」**（唯一有命理传统的做法，且**可复算**）：

- 以**中国地理中心**（约 103°E / 36°N，兰州—西安一带）为原点
- 按城市经纬度算**方位角**，归入八方 + 中央：
  - 东 → 木｜东南 → 木(次火)｜南 → 火｜西南 → 土(次火)
  - 西 → 金｜西北 → 金(次水)｜北 → 水｜东北 → 土(次水)｜中央 → 土
- **`reason` 里写明实际方位角**（如「北京：位于中心点北偏东约 8°，判水」）

**次五行 `wx2`** 保留地气物产取象，但**在 `reason` 里标注**（如「次五行土：皇城厚土，属产品设定」）。

## 3.3 要求

- `wx`（主）**必须**是可从经纬度复算的方位五行
- `wx2`（次）可保留特色取象，但 **`reason` 里必须能看出哪套是哪套**
- 提供一个小脚本或函数，输入经纬度输出方位五行，**可复验**
- 页面已加的合规声明**保留**（依旧要说清这是产品设定）

> **若你认为"物产取象"更合适**，也可以 —— 但**必须统一用一套**，
> 并在 `reason` 里逐条注明。**不允许两套混用而不标。**
