# 一、P1-1：修检查脚本第 4 项的「否定式误报」

## 1.1 问题复现

我复跑 `npm run verify:ai` 得到 `AI_COMPLIANCE_FAIL（3/4）`：

```
========== aiHemun 合婚 ==========
✗ 典籍与民俗/古法/产品设定同句并列：
  「四、婚期与近一两年节奏：男命当前行甲申运（助运），女命当前行甲辰运（耗运），
    此为大运同步的产品设定参考指标，仅作节奏参考，非命理典籍所载」
```

**这句话是合规的** —— 它明确**否认**了典籍归属：

> "此为大运同步的**产品设定**参考指标…**非命理典籍所载**"

## 1.2 根因

`test-ai-compliance.mjs` 现行第 4 项：

```js
const bad = splitSentences(text)
  .filter(s => s.includes('典籍') && /生肖|纳音|大运同步/.test(s))
```

**它只判断「两词是否同句出现」，不区分「肯定」与「否定」。**

## 1.3 改法（★ 以下正则我已实测 10/10，直接用）

**把"一档判定"改成"两档"**：

```
✗ FAIL —— 同句出现 (生肖|纳音|大运同步) 与 典籍，且【无】否定标记
ℹ️ INFO —— 同句出现两者，但【有】否定标记  → 打印出来，但不判失败
```

**为什么要分两档，而不是直接排除否定句？**

> 如果只做排除，**一句同时含"肯定表述 + 否定表述"的真违规会被静默放过**。
> **降级为 INFO 而不是丢弃** —— 误报不再假红，但信息仍在，人工可复核。

### 关键设计：否定词必须**紧邻**「典籍」

**这是本判据的要害。** 我第一版只查「典籍**前**的否定词」，实测 8 例中错 1 例
（「典籍**无**此判据」否定在后，未覆盖）。

**但也不能放宽成"同句任意位置有否定词"** —— 那会把真违规救走：

```
真违规：「生肖配对源自典籍所载，并非民俗之谈」
        ← 断言"源自典籍"，只是否认"是民俗"
        若允许同句任意否定 → 被误判为 INFO，漏掉真违规 ✗
```

**所以：否定词须在「典籍」前后各 3 字以内。**

```js
const BASIS_CONFUSE = /生肖|纳音|大运同步/

// 否定词紧邻「典籍」：前 3 字内，或后 3 字内
const NEG_NEAR_DIANJI =
  /(非|不是|并非|不属于|无|不载于|未载|有别于)[^。；]{0,3}典籍|典籍[^。；]{0,3}(无|不载|未载|非|不是|没有)/

const sentences = splitSentences(text)
const confused = sentences.filter(s => BASIS_CONFUSE.test(s) && s.includes('典籍'))

const fail = confused.filter(s => !NEG_NEAR_DIANJI.test(s))
const info = confused.filter(s =>  NEG_NEAR_DIANJI.test(s))
// FAIL 判定只看 fail；info 照常打印（标 ℹ️）
```


**ℹ️ 那行必须打印** —— 它是"我们没有静默丢弃"的证据。

# 二、P1-2：用例扩至 ≥3，并声明「抽样」性质

## 2.1 为什么

**同一份代码，你跑 4/4、我跑 3/4** —— 因为 **AI 输出是非确定性的**：
模型每次措辞不同，是否触发误报随之变化。

**所以「4/4 PASS」不是稳定保证，只是那一次抽样的结果。**

## 2.2 改法

**每个模块固定 3 个用例**（不是 1 个），且**用例须有差异**：

| 模块 | 用例要求 |
|---|---|
| aiAnalysis 批命 | ①**回归用例**（辛未 壬辰 壬子 壬寅 男）②身弱财官旺型 ③女命 |
| aiHemun 合婚 | ①**原测试对**（男 1990-5-8 16:30 / 女 1992-8-15 9:00）②一对明显逢冲/多忌的 ③一对日柱相合/多吉的 |
| aiGeo 地理 | ①**广州**（原用例）②内陆中心（如西安）③边陲（如乌鲁木齐或三亚） |
| aiZiwei 紫微 | ①**回归用例** ②身弱型 ③女命 |

> **回归用例必须保留在每一组里**（它是我们的基准盘）。
> 其余两个请自行选**走不同代码分支**的命例，不要选三副相近的。

## 2.3 结论表述要求

**汇总行必须写明抽样性质**，不得表述为"已保证合规"。参考：

```
AI 合规抽验（4 模块 × 3 用例 = 12 次调用）
  aiAnalysis  3/3 ✓
  aiHemun     2/3 ✗（见下）
  aiGeo       3/3 ✓
  aiZiwei     3/3 ✓
AI_COMPLIANCE_PARTIAL（11/12）
※ 本结果为单次抽样；AI 输出具非确定性，不构成稳定保证
```

**并请在回传里报出实际调用次数与 token 用量**（便于评估成本）。

## 2.4 可选（若你判断有价值）

**同一用例连跑 2 次**，用以**量化波动率**。
若采用，请单列"同例重跑一致率"，不要混进主结论。

# 三、P2-3：紫微事实集与 prompt 对齐

## 3.1 问题

`test-ai-compliance.mjs` 的紫微事实集：

```js
const facts = new Set([
  ...chart.palaces.map(p => p.ganZhi),   // ← 十二宫干支
  a.decadal.ganZhi, a.yearly.ganZhi, a.xiaoxian.ganZhi
])
```

但 `aiZiwei.ts:52-60` 的 `palaceBlock` **只给星曜/吉星/煞星/标签，不给宫干支**。
（运限三个干支 prompt 有给，见 `aiZiwei.ts:88-90` ✓）

**→ 事实集比 prompt 宽**，检查因此偏松。

## 3.2 原则与推荐方向

**原则：事实集必须 ⊆ prompt 实际给出。**

两个方向都满足原则，**推荐 (a)**：

| | 做法 | 效果 |
|---|---|---|
| **(a) 推荐** | 把十二宫干支**补进 prompt** | 宫干支是命盘确定性信息，写进 prompt 让解读更有据；检查同时保持严格 |
| (b) | 从事实集**移除**宫干支 | 更保守（检查更严），但报告里就不能提宫干支 |

**若选 (a)**：在 `palaceBlock` 每宫后追加干支，如
`命宫（戊戌）：紫微、天府；吉星：…`

# 五、必须避免
