## 2.3 ⚠️ 但检查脚本有一个「否定式误报」缺陷

**我独立复跑 `npm run verify:ai`，得到 `AI_COMPLIANCE_FAIL（3/4）`：**

```
========== aiHemun 合婚（全文 1718 字）==========
✓ 依据分级出现 4 类：典籍、古法、民俗、产品设定
✗ 典籍与民俗/古法/产品设定同句并列：
   「四、婚期与近一两年节奏：男命当前行甲申运（助运），女命当前行甲辰运（耗运），
     此为大运同步的产品设定参考指标，仅作节奏参考，非命理典籍所载」
```

**这一句其实完全合规** —— 它说的正是：

> "此为大运同步的**产品设定**参考指标，仅作节奏参考，**非命理典籍所载**"

**它明确否认了典籍归属，正是我们要求的行为。**

**问题在检查脚本第 4 项的正则：**

```js
const bad = splitSentences(text)
  .filter(s => s.includes('典籍') && /生肖|纳音|大运同步/.test(s))
```

**它只看"是否同时出现"，不看"是肯定还是否定"。**
句子中出现「非命理典籍所载」这种**否定式**时，会被误判为"混淆依据"。

**改法**：加否定排除。

```js
.filter(s => s.includes('典籍') && /生肖|纳音|大运同步/.test(s)
  && !/非.{0,6}典籍|典籍.{0,6}所载|不是典籍|并非典籍|非.{0,4}典籍所载/.test(s))
```

## 2.4 ⚠️ 并且这个测试是 **flaky** 的

**同一份代码，你跑出 4/4，我跑出 3/4。** 原因是 **AI 输出非确定性**——
模型每次措辞不同，是否触发误报随之变化。

**含义**：

> **「4/4 PASS」不是一个稳定的保证。** 它只说明那一次抽样的输出合规。
> 换一次运行、换一个命例，结论可能不同。

**这不否定本轮成果**（AI 本身确实合规，见 §2.5），但它意味着：
**这个验收脚本必须修掉误报，否则以后会周期性"假红"，消磨我们对它的信任。**

# 五、总纲回写

本轮产生**一条新的验收原则**，已回写总纲 §8.4：

> **8.4.5 模式匹配式检查必须处理「否定式」**
>
> 用关键词/正则检查合规性时，**必须区分"肯定"与"否定"**。
> 「非命理典籍所载」「不作绝对断言」这类**正确表述**，
> 会被"同时出现两个词"式的粗正则误判为违规。
>
> **并且：AI 输出的验收本质是「抽样」**，单次 PASS 不构成稳定保证。
> 应固定多个用例、并在结论里注明抽样性质。
