# 二、★ 返修 A：城市五行去退化（P0）

## 2.1 问题与根因

**现状**：86 城主五行分布（`wx`，方位五行，以中国地理中心 103°E/36°N 为原点）：

```
木  53 城  62%
金  12 城  14%
火  11 城  13%
土  10 城  12%
水   0 城   0%   ← ★
```

**按方位角分区：**

| 方位 | 城市数 |
|---|---|
| 北(水) | **0** |
| 东(木) | 32 |
| 东南(木) | 22 |
| 南(火) | 11 |
| 东北(土) | 7 |
| 西(金) | 9 |
| 西北(金) | 4 |
| 西南(土) | 1 |

**根因**：中国主要城市**都在 103°E 以东**，所以"东+东南"吃掉 63%；
"正北"扇区（正北 ±22.5°）在中国境内**没有城市**（那里是蒙古／西伯利亚）→ **水永不可达**。

**后果是功能性缺陷**：任何喜用含水的命主（如**木日主的贵人之城＝印＝水**）**永远推荐不出水城市**。

> ⚠️ **你的实现没问题**——`bearingFromOrigin` 用了 `cos(lat)` 修正、45° 分八方、自检一致。
> **是规格错了**（我在任务书 §3.2 写的"以中国地理中心为原点"）。

## 2.2 ⚠️ 我上一轮的建议不够（已实测）

我在复核对执里建议"把 `wx` 与 `wx2` 角色对调"。**但我实测后发现这不解决问题**：

| 赋值 | 分布 | 缺口 |
|---|---|---|
| `wx`（方位五行） | 木53 / 土10 / 火11 / 金12 | **水 = 0** |
| `wx2`（地气取象） | 水37 / 金23 / 木14 / 火12 | **土 = 0** |

**两个都退化，只是缺的五行不同。对调 = 把洞从"水"挪到"土"。**

（`wx2` 缺土的原因：取象词汇集中在"港口=水／煤铁=金／森林=木／炎热=火"，**没有城市被贴上"土"的取象**。）

## 2.3 正确改法：方位必须**相对命主出生地**计算

**核心洞察（总纲 §8.4）：**

> **「方位五行」是「方位对某个人的影响」，不是「对象相对某原点的固有属性」。**
>
> 把"相对"的量当成"绝对"属性来用，在**中心周围分布不均**的对象集上必然退化。
> 而**"相对命主"的方位，结构性不可能退化**——任何用户周围 360° 都有城市。

### 改法

| 维度 | 性质 | 怎么算 | 依据等级 |
|---|---|---|---|
| **方位五行** | **相对关系** | **按命主出生地**算每个城市的方位角 → 归八方 → 五行 | **典籍**（方位五行有命理传统） |
| **城市地气** | **固有属性** | 城市自身的地理/物产特征（现 `wx2` 的内容，可扩编） | **产品设定**（须声明） |

**具体做法：**

1. **「是否有候选」只由方位决定。**
   对每个候选城市，算它**相对命主出生地**的方位角 → 八方 → 五行，
   与目标五行比对 → 决定是否入选。
   —— 因为用户周围八方都有城市，**每个五行都必有候选**（结构上不可能退化）。
2. **`wx` 字段重新定义**：不再叫"方位五行"，改为**城市固有地气**（产品设定）。
   保留作**次要加分**（如"地气与命局相合，+6"），**不参与"是否有候选"的判断**。
3. **`reason` 逐条写明两套来源**：
   ```
   方位：位于出生地X方（方位角约X°），按方位五行判X（相对命主）
   地气：X（地气物产取象，属产品设定）
   ```
4. **现有 `direction` 字段**正是这个机制，把它**从"加分项"升格为主判据**。

### 关于 `geo-cities.json` 的数据结构

城市**不再需要预标"方位五行"**（那是相对量，存不住）。
建议：

```jsonc
{
  "name": "北京",
  "lat": 39.9, "lng": 116.4,
  "diqi": "金",          // 城市固有地气（产品设定，原 wx2 内容或扩充）
  "diqiReason": "政金肃敛（地气物产取象，属产品设定）"
  // 不存"方位五行"——它由「城市坐标 + 命主坐标」实时算出
}
```

## 2.4 验收（★ 硬门槛）

```bash
# 随机抽若干出生地，验证八个方位都有城市候选
node -e "
// 抽 10 个不同出生地（如 广州/北京/乌鲁木齐/哈尔滨/昆明/上海/成都/拉萨/西安/三亚）
// 对每个出生地，统计八方各有几个城市
// 要求：每个方位 ≥1 城
"
```

| # | 指标 | 期望 |
|---|---|---|
| 1 | 任一出生地下、八个方位**各自的城市数** | **全部 > 0** |
| 2 | 任一五行（木火土金水）的可达性 | **全部 > 0**（对任意出生地） |
| 3 | 单一五行占比 | **< 50%** |
| 4 | `reason` 能看出哪套是哪套 | ✓ |
| 5 | 合规声明保留 | ✓ |

> **注意**：验收 #1 是**关键**——它把"不退化"从"数据凑得匀"变成"**结构性保证**"。

# 三、★ 返修 B：财运维度恢复区分度（P0）

## 3.1 问题与根因

**现状**（辛未 壬辰 壬子 壬寅 男，9 步大运）：

```
带财星的大运:  丁亥【滞】  丙戌【滞】
不带财星的大运: 辛卯【滞】 庚寅【滞】 己丑【滞】 戊子【滞】
                乙酉【滞】 甲申【滞】 癸未【滞】

财运 note 去重后仅 2 种文本（差别只在末尾一句"比劫再临"）
四维度区分度:  career 5/9  |  wealth 2/9  |  health 2/9  |  relation 2/9
```

**丁亥（正财透干）、丙戌（偏财透干）这两步财运最强的运，与一步财星都不来的运，判定完全相同。**

**根因**（`src/lib/analysis.ts` 约第 809–818 行）：

```ts
// 财运：命局若比劫林立 + 财星深藏，则任何大运求财皆费力，比劫运尤忌   ← 注释已自承
const biJie = biJieCount(chart)                    // ← 纯原局
const chartCaiShenCang = godOnlyCang(chart, [...]) // ← 纯原局
if (v.biJieDuoCai || (biJie >= 2 && chartCaiShenCang)) {   // ← 后半段对全部大运恒真
  wealth = { tendency: '滞', note: '…求财费力…' }
} else if (v.caiXingShenCang) { … }
  else if (isCai) { … }    // ← 专门处理"大运带财"的分支，对本盘【永远不可达】
```

**你在 `analyzeValidity` 里做对了大运门控**（只有大运带财才置 `caiXingShenCang`），
**但被 `buildDomains` 的原局兜底条件短路了。**

## 3.2 为什么这是问题

**这是原问题倒过来的那一面：**

| | 表现 | 性质 |
|---|---|---|
| 改之前 | 把该守的十年说成「大吉、积极进取」 | **过度乐观** |
| 改之后 | 从 3 岁到 83 岁全说「求财费力」 | **过度宿命** |

**两者都是给用户错误信息。** 而这张盘里这两个运**真的不一样**：

- **丁亥**：正财透干，是「财现」之运——虽丁壬合、坐亥比肩（守不住），但**机会出现了**
- **辛卯**：财不现，只能靠伤官间接生财

「财来了但守不住」与「财根本没来」，**感受和应对是两回事**。

## 3.3 改法

**原则：原局特征应在「命局总论」说一次；时段维度只讲该时段带来的变化。**

调整第 814 行的**条件优先级**：**先判「大运是否带财」，再叠加原局特征**，
不让纯原局条件无条件抢先：

| 大运类型 | 财运倾向 | 措辞方向 |
|---|---|---|
| 无财星 | 【滞】 | 求财费力，宜凭专业积累 |
| **财星透干** | **【平】** | **财现但比劫夺之——进财机会与破耗并存，宜守不宜投** |
| 比劫运 | 【滞】 | 破耗之险更甚 |

同时：**"比劫林立＋财星深藏"作为命局特征，在「命局总论」里说一次**，
不要在大运里重复 9 遍。

## 3.4 验收

```
① 带财星大运的财运倾向 ≠ 无财星大运的财运倾向
② 丁亥/丙戌 的措辞须体现「财现但易破」
③ 回归用例：己丑运仍须 财运【滞】、事业【平】、出现"忌杠杆投机"
④ 不得回退到「大吉」（回归测试须仍 SELFTEST_PASS）
```

# 六、一句话

> **两处返修是同一个病：分布退化。**
>
> - **城市五行**：把"相对命主的方位"误当"城市固有属性"→ 水永远取不到。
>   **改法不是对调数据，而是承认它是相对量、按命主实时计算。**
> - **财运维度**：把"原局特征"误当"时段判定"→ 所有时段一个结论。
>   **改法不是调权重，而是让时段判据真的依赖时段。**
>
> **共同点：一个量如果是"相对的"或"时变的"，就不能当成"绝对属性"或"常量"来用。**
