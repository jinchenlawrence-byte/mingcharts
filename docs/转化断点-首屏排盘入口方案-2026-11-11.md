## 一、生肖流年页首屏入口

### 1.1 结论

做。但**不做「按当前页属相估算」那种伪入口**，做一个 3 字段的轻量排盘表单，放在 H1 关系卡之后、第一段运势之前。

### 1.2 放什么控件

**方案：年 / 月 / 日 三个下拉 + 性别 + 「先看我的命盘」按钮；时辰留空，默认 12:00，结果页顶部提示补时辰。**

理由：

1. **时辰是最大流失点**——大量用户不知道自己的出生时辰。首页 hero 要求填时、分，等于在第一步就筛掉一半人；日页（[/bazi/[year]/[month]/[day]/page.tsx](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/(zh)/bazi/[year]/[month]/[day]/page.tsx#L75-L83)）早就用「默认午时」绕开这个问题，同一套逻辑可以复用。
2. **三个下拉能把首屏高度控制在 1 行**（移动端两行），不把 H1 挤出首屏。
3. **不放「按属相年龄估算」**：属相到年份是多对一（属龙可以是 1988/2000/2012…），估算出来的不是命盘，无法在 `/chart` 承接；用户点进去发现「不是我要的」，比现在不点更伤。

### 1.3 放在哪个区块

插入点：[ShengXiaoYearView.tsx](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/components/shengxiao/ShengXiaoYearView.tsx#L94-L107) 的 H1 关系卡（`hw-c-box mb-6`，L94-103）之后、`copy.sections.map`（L105）之前。

```
[面包屑]
[H1 + 吉凶徽章 + 关系说明]        ← 现状
[★ 新增：首屏排盘入口卡]          ← 新增，首屏内
[全年总运 / 事业 / 财运 / 感情 / 健康]
[开运建议] [FAQ] [上下年] [延伸阅读]
[页尾 CTA]                        ← 保留，见 1.4
```

桌面：入口卡内左右两栏——左「想看 2028 年你个人的运势？生肖只是 1/12」文案 + 右表单（年月日一行、性别与按钮一行）。
移动：单列；年月日三个下拉用 `grid-cols-3`，性别用分段按钮，按钮整宽。

### 1.4 与现有 hero / 页尾 CTA 的关系

**并存，但要改写分工**：

| 位置 | 现状 | 改后 |
|---|---|---|
| 首屏新入口 | 无 | 轻表单（年月日 + 性别），提交即出盘 |
| 页尾 `hw-c-cta`（[L172-180](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/components/shengxiao/ShengXiaoYearView.tsx#L172-L180)） | 「输入时辰，排我的八字 →」跳 `/` | 改为「补充出生时辰，看完整命盘 →」，跳同一表单（可带预填参数） |
| 页尾付费入口 `annualHref = /liunian`（[L339](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/components/shengxiao/ShengXiaoYearView.tsx#L334-L339)） | 保留 | 保留，不动 |

不替换页尾 CTA 的原因：读完 5 段运势的人是另一批高意图用户，页尾是他们的自然出口；替换会让这批人直接断掉。

### 1.5 技术代价

| 项 | 评估 |

| 新增组件 | 1 个客户端组件（约 120–150 行）`BirthQuickForm`。**不能直接复用 [BirthForm.tsx](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/components/BirthForm.tsx)**：它是 5 个 `number` 输入、时辰必填、提交字段是 `birthPlace` 而非首页用的 `birthCityId/birthZone`，且**不记 `paipan_submit` 埋点**。建议把「提交 + localStorage + 跳 /chart」抽成共用函数，两条表单各自保留 UI。 |

**建议暂不做。** 收益不明确，代价贯穿路由、导航、SEO 与埋点。

| sitemap | [sitemap.ts L24-50](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/sitemap.ts#L24-L50) 是手工清单，需加条目并定 priority |

'/'`（[article/[slug]/page.tsx L187](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/(zh)/article/[slug]/page.tsx#L187)）、日页 6 处 `Link href="/"`、`BirthForm` 默认跳转、首页内部链接——漏一处就出现两套入口 |

## 三、`/bazi` 的 CTA 缺口

### 3.1 结论

**这 0 点击是「页面本身没被点进去」，不是「进去了没人点 CTA」。在页面里加 CTA，对当前的 0 点击没有任何帮助。**

### 3.2 依据

| 指标 | `/bazi` 全部 274 页 | 其中月页 1990–2010（noindex 后仍索引） | 其中年页 |
|---|---:|---:|---:|
| 展示 | 1,449 | 706 | 140 |
| 点击 | 0 | 0 | 0 |
| 平均排名 | 8.86 | 8.29 | 11.86 |

- 0 点击意味着 **Google 上 0 次进入**，页面内的按钮再好也没人看见。
- 平均排名 8.29 在第 1 页底部，按 0.5%–1% 的经验 CTR，706 次展示应对应 3–7 次点击，实际 0；年页均位 11.86（第 2 页），0 点击属正常，但同样说明问题在「搜索结果里的标题/摘要」，不在页内。
- 这批页的标题已于 2026-11-10 改过（[bazi/[year]/[month]/page.tsx L38-44](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/(zh)/bazi/[year]/[month]/page.tsx#L38-L44)），仍在 GSC 2–3 天延迟窗口内，**现在加 CTA 等于在还没人进的房间里装指示牌**。

### 3.3 该做什么

1. 先不补 CTA。等 11-10 那次标题改动满 2–4 周，看月页 CTR 是否离开 0。
2. 若 CTR 仍为 0：问题是查询意图与页面不匹配（用户搜「2005年1月出生属什么」只想要一个答案，不需要进站），此时正确动作是摘要/结构化数据，而不是页内按钮。
3. 页内 CTA 只在「站内会有人进入」时才值得补。目前无证据显示有站内流量进入 `/bazi`（`events` 未按路径细分首页以外来源，**无法确认**）。若将来补，优先级也低于生肖页。

## 四、埋点校验

### 4.1 现有 4 个事件覆盖到哪

| 链路环节 | 现有事件 | 覆盖 |
|---|---|---|
| 落地页浏览 | `page_view`（含 `path`） | ✅ |
| 首屏入口**曝光** | 无 | ❌ |
| 首屏入口**点击** | 无（CTA 全是 `<Link>`，无 `track`） | ❌ |
| 表单提交 | `paipan_submit`，**仅首页 HomeClient 记**（[HomeClient.tsx L124-129](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/(zh)/HomeClient.tsx#L124-L129)） | ⚠️ 部分 |
| 结果页试读 | `preview_view` | ✅ |
| 购买点击 | `pay_click` | ✅（但覆盖不全，见 4.3） |

**结论：覆盖不了「曝光 → 点击 → 提交」这条链。** 现在只有「提交」一环，且提交事件里的 `path` 恒为 `/`，无法归因到是哪一篇生肖页/文章页把人送进来的。改动上线后，也只会看到提交数变化，看不到是哪个入口起作用。

另有一个现成漏记：[BirthForm.tsx](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/components/BirthForm.tsx#L36-L67)（`/mingshu` 在用）提交成功**不记** `paipan_submit`，这批排盘目前在数据里完全不可见。

### 4.2 要补的事件（按优先级）

| 事件 | 参数 | 用途 |
|---|---|---|
| `paipan_cta_click` | `slot`（hero/bottom/nav）、`src`（当前 pathname） | 判断首屏入口有没有被点 |
| `paipan_cta_view`（可选） | `slot`、`src`，IntersectionObserver 50% 触发一次 | 区分「没看到」与「看到没点」 |
| `paipan_submit` 加 `src` | 落地页 path（sessionStorage 记首次落地页） | 把提交归因到 2028/文章页 |
| `BirthForm` 补 `paipan_submit` | 同首页 | 补齐 `/mingshu` 漏记 |

实现约束：`TrackName` 联合类型（[track.ts L8](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/lib/track.ts#L8)）与 `/api/track` 白名单（[route.ts L9](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/api/track/route.ts#L9)）必须同时改，否则事件被 400 丢弃；props 上限 8 键、字符串 120 字（[route.ts L29-39](file:///e:/ai-agent/MINGCHARTS/bazi-mvp/src/app/api/track/route.ts#L29-L39)）。

## 五、如果只做一件事

**做「生肖流年页首屏轻量排盘入口」。**

理由三条：

1. **它对着最大的流量池**：88 次点击里 76 次（86%）落在这里，其中 57 次在 2028 页；这些人到了页面，却要滚过 565–692 个字才看见第一个排盘入口。
2. **断点就在这一步**：906 个会话只有 13 个提交过排盘（1.4%），而排过盘的人里有 10 个进了试读——后面并不窄，是入口太远。
3. **改动最集中**：一个共用组件 + 一个新组件，288 页与三语一次生效；不新增路由、不改 metadata、不动 canonical，回归面最小。

配套不做的事：

- 不建 `/paipan`：与首页 hero 重复、要改全站链接与埋点口径、分散唯一的排盘入口权重。
- 不给 `/bazi` 加 CTA：0 点击是「没人进来」，不是「进来不点」。

**前置条件**：先补 `paipan_cta_click` 与 `paipan_submit` 的 `src` 归因，否则这次改动上线后无法验收——只能看到提交总数变了，说不出是不是首屏入口带来的。
