## 一、引擎层：显式禁用，绝不喂 12:00

### 1.1 数据契约

每个维度改为带状态，而不是只返回分数：

```ts
type DimensionStatus = 'calculated' | 'skipped_missing_hour'
interface HemunDimension {
  key: string
  name: string
  status: DimensionStatus
  requires: ('hour' | 'fourPillars')[]   // 声明式，不做 if-else 散落在各处
  level?: '吉' | '平' | '忌'            // status=skipped 时不存在
  delta?: number                         // 同上
  reason?: string                        // 「需完整四柱（配偶星落时）」
  facts?: string[]
}
interface HemunResult {
  mode: 'four-pillar' | 'three-pillar'
  missingPillars: ('hour')[]
  dims: HemunDimension[]
  overall: null                          // 三柱模式下必须为 null，不是 0、不是 '平'
  grade: null
  totalScore: null
}
```

**三条硬约束**：

1. `status = 'skipped_missing_hour'` 的维度**不产生 level / delta**，字段为 `undefined`，禁止用 0 或「平」占位；
2. 三柱模式下 `overall / grade / totalScore` 一律 `null`，前端不渲染对应区块；
3. 排盘层要支持「时柱为 null」的盘，**不允许先按 12:00 排出四柱再打标记**——后者会让五行统计、藏干、地支关系全部失真。

### 1.2 实现方式（推荐：声明式 + 运行时过滤）

- 每个维度的计算函数外加一张静态表 `DIM_REQUIRES`（`key → requires[]`）；
- 入口 `computeHemun(male, female, { hourKnown })` 先按 `requires` 过滤，未满足的直接产出 `status: 'skipped_missing_hour'`，**不调用计算函数**；
- 这样「禁用」是代码层开关（一张表 + 一层过滤），而不是在 9 个函数里各写一遍 `if (!hour) return`——后者容易漏，也容易被后人改回默认值。

### 1.3 前端如何区分「未计算」与「计算结果为空」

| 情形 | 后端 | 前端 |
|---|---|---|
| 三柱模式，维度需时柱 | `status='skipped_missing_hour'` + `reason` | 渲染为「未计算」占位条：灰底、无分数条、写明「需完整四柱（原因）」，附「补时辰」按钮 |
| 四柱模式，计算成功但结论中性 | `status='calculated'`, `level='平'` | 正常渲染中性色，不显示「未计算」 |
| 计算异常/数据缺失 | 接口返回错误或 `dims` 缺失 | 显示「数据异常，请重试」，**不得**降级成「未计算」 |

关键：**「未计算」是显式状态，不是空字符串**。前端禁止用 `!dim.level` 之类的判断来推断未计算——那会把「平」也吞掉。

## 二、生肖与纳音的处置（建议，未动代码）

### 2.1 呈现

| 模式 | 生肖配对 | 年柱纳音 |
|---|---|---|
| 四柱模式 | 保留，但移到列表**末尾**，标注「古法·参断」，**不加分数条**、不参与总分 | 同上，标注「《五行精纪》古法，非子平主断」 |
| 三柱模式 | **默认折叠**（放在「古法参断」折叠区，不进入三项主判断） | 同上 |

理由：三柱模式下只剩日支、日干、透干三件事能站住；此时把生肖放在显眼位置，用户会把它当成结论，强化「看生肖相冲就下结论」的错误认知——这正是文章要纠正的东西。

### 2.2 措辞与权重

- 主断层（夫妻宫、日干生克、配偶星透干）：正文位置，每条带经典出处（如「《三命通会》妻宫断」）；
- 参断层（生肖、纳音、神煞）：折叠区，标题写「古法参断（不作主断）」，条目不使用「吉/忌」色块，改为中性文字；
- **不与主断层混排**，避免用户把「生肖六合」理解为「合婚很好」。

### 2.3 一句话建议

生肖维度**保留但降权**：四柱模式折叠置底、三柱模式默认隐藏，全部标注「古法参断」，不参与任何评分与结论。

## 四、免费 / 付费边界

三柱模式下能给的本来就只有三条，因此**免费层把这三条都给**，付费价值放在「补时辰后的完整九维 + 化解」。

| 层 | 内容 |
|---|---|
| 免费（不登录） | ① 夫妻宫关系的**完整判词**（最扎眼的一条）；② 双方日干生克一句；③ 配偶星透干一句；④ 六项「未计算」说明 |
| 免费（登录） | 上述 + 保存到「我的报告」 |
| 付费 | 补时辰后的完整九维、每项的化解建议、AI 解读、追问 |

**钩子怎么落地**：免费层唯一的戏剧性来自夫妻宫。写法要具体但不下死判，例如：

> 「你的夫妻宫是子，对方是午——**子午正冲**。夫妻宫被冲，主聚少离多、争执起得快也散得快；这类组合最怕在婚后第三到五年把话憋着不说。」
> 下面接：「这不是判死刑：冲有冲的开法，需看时支是否通关、以及双方旺衰。补上时辰可看完整判断。」

要求：
- 用「易/主/最怕」而非「必定」；
- 结论后立刻给悬念（时支是否通关），但不给答案；
- 不给「冲=凶」的单一解释，避免制造恐慌式转化。

## 五、分享链接与 OG

| 项 | 方案 |
|---|---|
| 承载 | 签名 payload：`/hemun/r?d=<payload>&s=<hmac>`，payload 只含「模式 + 双方日支 + 日主 + 三项标签」，**不含完整生日** |
| 计算 | 服务端验签后用规则引擎重算（确定性），不查库、不调 AI |
| index | **`noindex, follow`**。理由同方位之城方案：组合无限 + 隐私 + 与 `/hemun` 重复 |
| OG 图 | 用 `next/og` 生成 1200×630：`子午正冲 · 夫妻宫相冲` + 两个日主 + 域名；不带生日 |
| 有效期 | 链接 30 天过期（HMAC 内嵌 exp），换密钥即全失效 |
| 分享入口 | 结果页一个按钮，`navigator.share` 优先，降级复制 |

注意：三柱模式的分享页**只能出现三柱结论**，不得因为「分享页想好看」而补上未计算的维度。
