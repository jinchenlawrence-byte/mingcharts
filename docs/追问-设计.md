# AI 追问（ask_pack）设计稿

> 依据 `docs/定价方案.md §8.1`：追问属独立于日运/日签的单独需求，实时 AI 生成、不可逐条审核、
> 风险高，须先出独立设计稿（拒答清单、改写法、运行时合规、免责、额度费率）。

## 一、定位与入口

- **产品形态**：独立额度包（`ask_pack`，$4.99 / `ASK_PACK_SIZE`＝15 次），**不属于会员订阅**。
  订阅权益（`SUBSCRIPTION_GRANTS`）本轮**不含** `ask`；会员每月赠送额度留待下一轮。
- **入口**：内嵌 `/chart` 结果页「解锁后」区域（已购命书可见），**不做独立 `/ask` 页**。
- **购买入口**：`/pricing` 「追问包」区 + 追问面板额度耗尽处。
  `waffo-products.ts` 未登记 `ask_pack` 的 `PROD_` id 时，入口显示「即将推出」（属预期）。

## 二、额度模型（派生，无可变计数器）

- **已授予** = 已支付【真实】`ask_pack` 流水数 × `ASK_PACK_SIZE`。
  - `ask_pack` 一次性购买经现有 checkout/webhook 落库为 `payments(payment_type='single', sku='ask_pack')`，
    `transaction_id` UNIQUE 天然防重复授予 —— **无需新增加额逻辑**。
  - `MOCK_` 前缀模拟流水不授予（与 `entitlementsFromRows` 同口径）。
- **已消耗** = `ask_messages` 表行数（**仅**AI 成功且过合规的行；拒答/失败不落行）。
- **剩余** = max(0, 已授予 − 已消耗)。
- 次数只在 `pricing.ts` 定义一处（`ASK_PACK_SIZE`）；额度判定只在 `entitlement.ts`
  （`askCreditsFromRows` 纯函数 / `getAskRemaining` 读库）—— route / 组件不得各自写判定。
- **拦截开关**：沿用 `ENTITLEMENT_ENFORCE`。关闭（生产默认/内测）→ 只记录、不拦额度；
  开启（收费）→ 剩余 ≤ 0 时 `/api/ask` 返 402（`code: ASK_QUOTA_EXHAUSTED`）。

## 三、硬拒答清单（调用 AI **之前**判定，零成本、可逐条审核、不扣额）

命中即返回脚本化合规拒答，**不调 AI、不消耗额度**。类别与词面见 `src/lib/aiAsk.ts` 的
`ASK_REFUSAL_RULES`：

| 类别 | 覆盖 | 示例 |
| --- | --- | --- |
| medical | 医疗健康（疾病、手术、用药、诊断、怀孕…） | 「我是不是得了癌症」 |
| legal | 法律纠纷（官司、诉讼、合同、判刑、抚养权…） | 「我这场官司能赢吗」 |
| investment | 投资理财（股票、基金、期货、币、杠杆、房价…） | 「我该买哪只股票」 |
| life_death | 生死寿夭（寿命、能活多久、自杀…） | 「我还能活多久」 |
| life_decision | 重大人生取舍的「该不该/要不要」类 | 「我该不该辞职」 |

## 四、改写法（给依据，不给判决）

拒答话术**必含**「命局倾向 ＋ 你自己权衡」的改写示范：把「该不该做」引导为
「命局在某方面呈现什么倾向、依据是什么」，并提示参照对应专业意见
（医疗→执业医师 / 法律→执业律师 / 投资→持牌投资顾问）。由 `refusalText(category)` 生成，
断言自证不含禁用词。

## 五、运行时合规（复用 `ai-check.ts`，不自造判据）

- 生成前：绝不提交拒答类问题给模型。
- 生成后：`makeAskComplianceValidator` = ① `unknownGanzhi`（干支溯源，只用命盘事实）
  ② `findForbidden`（禁用词：确定性承诺 / 行动指令）。
- 不通过 → `withComplianceRetry`（首次留痕 + 带反馈整句重写一次）；仍不通过 → 放弃，
  返回合规**兜底话术**（`ASK_FALLBACK_TEXT`），**不扣额度**（问答类无规则版可回退，故不伪造规则版）。

## 六、免责与限量

- 每条回答固定附 `ASK_DISCLAIMER`（比报告更直白）：陈述命理为倾向性参考、非确定性结论，
  不构成医疗/法律/投资/人生决策依据。
- 限量：单条问题 ≤ `ASK_MAX_QUESTION_LEN`（300 字）；次数由 `ask_pack` 额度控制。

## 七、数据与安全

- 表 `ask_messages(id, user_id→profiles, chart_id→charts?, question, answer, created_at)`；
  迁移见 `supabase/ask.sql`（新库跑 `schema.sql` 即就位）。
- RLS：仅「本人 SELECT 自己历史」；写入走 `service_role`（`/api/ask` 服务端），客户端不可写。
- 端点：`POST /api/ask {token, chartId?, chart?, question}`；`GET /api/ask?token=` 取剩余次数。

## 八、验收

`scripts/test-ask-accept.mjs`（已入 `npm run verify`）覆盖：次数单一事实源、5 类拒答分类、
拒答/免责/兜底话术自证合规、`askCreditsFromRows` 边界、route 接线（拒答先于 AI、402、落库）、
合规示范自证。
